# 自动计算、玩家按钮与逐玩家条件比较

用户明确选择的模型：各玩家按当前已知牌分别比较，假设其他玩家之后不再补牌；每录一张牌自动更新，并在界面持续注明这一假设。这不是整桌未来行动策略模型，也不计算玩家之间的联合输赢概率。

## 操作

- 简洁面板右上角“− 玩家 / + 玩家”调整下一轮人数，1～7人。新增最低空座；减少最高的非本人座位。进行中的轮次、已录牌及冻结发牌顺序不变；点击“新开一轮”使用新配置。非连续座位仍在工作台逐个勾选。
- 自动默认开启；信息完整后延迟250毫秒计算选中玩家，其他玩家通过一个后台进程依次计算。最多同时两个已有有界计算进程，主界面继续录牌。取消会同时停止两者，下一次输入变化恢复自动计算。
- 多人时在原两项摘要区域显示七位玩家表：牌面、EV第1/第2动作各自净盈利概率、第1项EV和状态。点选行切换分析对象，录牌目标独立保留；详情继续显示选中玩家所有适用动作。
- 缺牌、规则未知、非BJ检查缺失、记录缺口、已选择但未录入的其他玩家必补牌等继续阻止不成立的比较。已经收牌结束的玩家显示相应状态，不显示新的操作建议。

## 计算与历史身份

`build_input`默认保持原单玩家门禁。只有显式`other_players_stand=True`才建立`per-seat-others-no-draw-v1`输入，保存真实参与顺序、目标身份、其他玩家已知牌事件身份和后续抽牌数0。所有已录牌都保留在同一有限不放回牌靴中；不改写账本、移除参与者或新增虚构停牌事件。

同一条件下沿用已验收的目标手牌/顺序两手求解器；目标后续行动仍使用原声明策略。因其他玩家后续抽牌固定为0，此条件模型不新增对其他玩家未来策略的枚举。范围标识和假设进入输入摘要、详情、存储快照及复算。历史复算恢复原前缀和同一条件口径；单玩家历史输入不变。

选中玩家继续通过原请求ID/输入摘要门禁发布。其余玩家共享一个队列工作进程；新记录提交先取消旧任务并清空所有旧结果，后台返回仅在账本上下文及输入摘要匹配时发布。保存失败单独标注，不回退为旧概率。数值公式、核心桌规和账本格式未改。

## 验证

新增测试覆盖：全部已知牌扣除、真实账本不变、默认接口拒绝默默改用多人模型、不同玩家同一庄家分布、历史前缀复算、必补牌与缺口、范围身份不可重贴、显式分牌/DAS模板继承；以及默认自动、增减人数下一轮生效、每玩家更新/旧行清空、取消双工作进程、七行最小窗口布局。
