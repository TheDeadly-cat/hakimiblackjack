# V0.2a 增量修复契约

本契约对应 2026-09-10 增量审查 R1—R3，保留原概率核心和数据库 schema 2。

## R1：跨轮观察完整性

`ROUND_ENDED` 增加可选字段 `observation_status`：`unknown`、`complete`、`incomplete`。新账本 API 默认写入 unknown；旧事件缺少该字段时只在重放派生状态中解释为 unknown，原事件、时间、身份和 JSON 不修改。即使旧事件已有结算结果，也不把缺失的观察声明补成完整。

结算与观察完整性独立。未结算交互提供明确的三状态选择，默认未知；自由文本原因不参与数学资格判断。正常“结束本轮并结算”操作代表确认牌面录入完成，并经结算校验后明确写入 complete。底牌等已记录的未知牌保留现有未知牌计数和分析限制，不因 complete 声明自动揭示。

重放记录结束事件 ID、轮次、声明状态、有效状态以及结构化缺牌代码。缺少庄家／参与玩家初始牌、分牌后第二张、已选择补牌／加倍但未收牌、仍需庄家补牌的可见终局，都使有效状态为 incomplete；用户声明 complete 不能覆盖这些事实。全部玩家爆牌或投降等不再需要庄家补牌的正向情况保留。未知／不完整状态持续影响同一牌靴，允许继续记下一轮，但精确分析返回 PRIOR_ROUND_OBSERVATION。

结束事件可追加 CORRECTION 修正 observation_status，必须写明核对依据；系统继续检测结构性缺牌，不允许声明抹除。补录漏掉的物理牌应逆序撤销到原轮、录入、重新结束，不能只改完整性标签。撤销结束／纠错事件后从原事件重放派生状态；历史前缀不使用未来纠错。换新牌靴重新建立观察状态。

旧原始事件仍可导入、恢复和导出，不迁移 SQLite；旧分析快照保留原结果。用当前代码复算历史输入时重新应用完整性契约，旧不合格输入可能被拒绝，而非修改旧判断。

对应测试：`tests/test_round_observation.py`。原 Tk 测试中两个“未结算结束”场景增加显式 unknown 选择桩，原记录、未知牌、恢复和快照断言均保留；实际新对话框另有真实控件测试。
