## 性能改进保留了失败证据

门槛先冻结为5秒硬请求预算和2秒p95目标。300个初始案例覆盖3副数×10对子×10庄家点值，另有18个动态前缀；没有剔除最慢案例或改变统计分母。

| 阶段 | 完成情况 | p95 / 最大 | 原始材料 |
|---|---|---|---|
| 第一轮工作树原型 | 317完成、1超时 | 2.745 / 5.015秒 | [首轮失败](acceptance/v02b1-20260911/first-cold-failed/) |
| 单手动作也接入加速器 | 318完成，p95目标未达 | 2.432 / 3.909秒 | [完整旧搜索参考](acceptance/v02b1-20260911/unbounded-reference/) |
| 加入保守信息收益界后 | 318完成、逐格差0 | 1.568 / 2.270秒 | [最终固定代码](acceptance/v02b1-20260911/accepted-3c5d7fb/performance/) |

上界只在能证明某个动作不可能更好时省去该动作搜索；没有采样、截掉小概率分支或拿基本策略冒充精确最优。尝试过但没有改善的哈希、缓存布局和并行原型未进入运行代码。

另有独立的9项组成压力检查：每种副数先通过完整已观察轮次移除全部十点牌、半数十点牌，或指定中间点值，再计算2/2对A。9项都完成，最大2.926秒。[压力记录与原执行脚本](acceptance/v02b1-20260911/depleted-stress/)单列，不混作预先冻结318样本。它仍不是对所有可达牌靴和所有硬件的耗时保证；超时必须保持无未完成数值的状态。

开发阶段完整219项首轮有一处测试把内存tuple与JSON array直接比较，随后改为规范JSON往返比较。该失败输出保留在 [development](acceptance/v02b1-20260911/development/)，不以新的源码身份重新签署。N1两条“v2展示器尚未安装”的阶段断言，已经替换为真实v2输入、展示与兼容测试，而非删除保障。

## 使用与复算

主程序仍为Python/Tk/SQLite。新增C#数值源码在 `blackjack_lab/analysis/native/SplitEngine.cs`，使用本机.NET Framework 4编译器；没有新增pip运行包或下载服务。构建采用源码快照，产物按源码摘要放在 `.local-native`，每次使用校验二进制摘要。Windows是本次交付平台。

三个 `fixtures/v02b1/` 示例全部标记为自建模拟器，分别展示分牌前、首手爆牌后第二手待发牌，以及分A普通21。它们不包含用户记录或真实牌局。

```powershell
python -m blackjack_lab.main --prepare-split
python -m blackjack_lab.main
python scripts/verify_split_release.py --compare-dir docs/acceptance/v02b1-20260911/unbounded-reference
```

每次验收输出到新的 `.local-evidence/` 目录。压力检查原脚本是当时从项目 `.local-evidence/` 执行的原文；若复跑，请在新副本中放回同层级，保留其已有输出目录，不能覆盖原压力记录。

交付采用新的桌面目录及源码/运行ZIP，原桌面版本、SQLite和`.analysis`目录不替换。源文件和示例与用户数据分开；继续自己的旧记录时，应先关闭程序同时备份数据库和同名`.analysis`，再显式选择原数据库。备份按钮仍只备份SQLite，完整安装升级、多DPI/多硬件、再分/DAS/多玩家EV仍属后续范围。
