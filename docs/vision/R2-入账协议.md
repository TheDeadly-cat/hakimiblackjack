# R2 人工确认入账协议

日期：2026-09-12  
范围：小范围适配 `controller.py` / `ledger.deal|reveal|correct`，新增 `ui/vision_bridge.py` 与核对窗口。不放宽分析门禁，不改求解器。

## 写入路径

1. 识别器只产生 `RecognitionResult`。
2. `VisionReviewSession` 绑定当时的 `session_id / shoe_id / round_id`。
3. 用户逐条确认。`request_id` 由绑定上下文 + 观察 + 人工决定哈希得到，并作为 `event_id`。
4. 控制器预演 → SQLite → 发布内存。失败不发布。相同 `event_id` 重试返回原事件，不增加 `commit_revision`。
5. `track_id = vision:{observation_id}`，与 `observation_id` 前缀区分；两张 8 是两个观察。
6. 来源固定 `识牌人工确认`，不被会话默认 `recording_source` 覆盖。
7. 仅当观察带有真实 `captured_at` 时写入 `observed_at`；模型运行时间不得冒充拍摄时钟。

## 操作

| 操作 | 控制器 |
|---|---|
| 新的可见牌 | `deal_shown(..., confirm_status=已确认)` |
| 确认已发出但看不清 | `deal_unknown(..., confirm_status=已确认)` |
| 新的暗牌 | `deal_hidden` |
| 揭示 | `reveal(target_event_id)` |
| 纠正 | `correct(target_event_id)` |
| 拒绝 | 不写账本 |

## 过期

换会话、换靴或换轮后，旧任务不能默认写入新上下文。尚未入账时可点“绑定到当前轮”。

## 界面

主窗口「识牌核对」。有未处理候选时红条「图像待核对」，旧 EV 不得当作已考虑本图。确认走 `app.fail()`，避免“账已写、界面报错后又点一次”。
