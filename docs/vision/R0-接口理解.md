## 已经可复用

- `Event.evidence`、`Event.observed_at`、`confirm_status`（`CANDIDATE` / `CONFIRMED`）、`source` 字段存在。
- `EventLedger.deal(..., evidence=, source=, event_id=, track_id=)` 已支持证据引用、幂等 `event_id`、同靴 `track_id` 防重复扣牌。
- 未确认候选不得按已知牌面扣牌；未知牌需 `unknown=True` 且不得携带猜测点数。
- `reveal(target_event_id, rank)` 用于暗牌翻面，不新增物理移除。
- 控制器有副本预演、SQLite 提交、`commit_revision` / `context_token` / 监听器。

## 已由 R2 关闭的缺口

1. `SessionController.deal_shown()` / `deal_hidden` / `deal_unknown` / `reveal` / `correct` 透传 `evidence`、`source`、`event_id`、`observed_at`。
2. `EventLedger.deal()` / `reveal` / `correct` 接收 `observed_at`；无采集时钟时不写入，禁止用识别时间冒充。
3. `_apply()`：未传 `source` 时仍套会话 `recording_source`（模拟器/手动录入）；显式传入时不覆盖。相同 `event_id` 已在账本中则返回原事件、不增加 `commit_revision`。
4. `observation_id` ≠ `track_id`。确认阶段写入 `track_id = vision:{observation_id}`。
5. 识别器仍不得直接写 SQLite；唯一入账路径是 `ui.vision_bridge` → 控制器。
