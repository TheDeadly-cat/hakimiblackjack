# GitHub / 现成软件：对「Chrome 窗口里认牌点数」有没有用

日期：2026-09-12  
问题：旁观 NVIDIA 录的 Chrome 直播牌桌，认出扑克点数。  
结论：**没有找到能直接装上就认这段窗口的现成软件或仓库。** 下面这些只是「做法可参考」，不能当成品。

## 没有现成可用的

- Chrome 扩展、Windows 识图、NVIDIA 录屏，都**不会**读二十一点点数。
- 直播桌的牌在**视频画面**里，不在网页 DOM。用浏览器自动化去“读页面上的牌”通常读不到。
- 网上一些“算牌/读牌”摄像头软件，针对的是**近距离实体牌**，不是浏览器里缩小的真人桌。

## GitHub 上实际有用的点（仅方法）

| 项目 | 有用在哪 | 对你这段录像没用在哪 |
|---|---|---|
| [EdjeElectronics/OpenCV-Playing-Card-Detector](https://github.com/EdjeElectronics/OpenCV-Playing-Card-Detector) | 流程清楚：深色底找白牌 → 拉正 → 切左上角标 → 和点数图比较 | 假定牌很大、互不重叠、没有绒面印刷字。Pi 摄像头近拍，不是 Chrome 远距桌 |
| [TeogopK/Playing-Cards-Object-Detection](https://github.com/TeogopK/Playing-Cards-Object-Detection) | 写明了：合成数据训出来的 YOLO，必须用**实拍同桌样本**微调才行 | 他们的权重不能直接套 Stake/Pragmatic 窗口 |
| [Raghuboi/card-detection](https://github.com/Raghuboi/card-detection) / Roboflow Playing Cards | 说明业界常用 52 类（点数×花色）YOLO，近距整牌 mAP 可以很高 | 训练集是摊在桌上的整牌照片，不是直播缩略图 |
| [tomalmog/CV-CardCounting](https://github.com/tomalmog/CV-CardCounting)、[umerfarok/Blackjack-card-detection](https://github.com/umerfarok/Blackjack-card-detection) | YOLO 检牌 + 跨帧跟踪这个方向是对的 | 自带模型对着你的窗口会差；且他们做的是摄像头算牌，不是账本确认入账 |

## 若要真正认出你这桌的点数

只能走「用你自己的录像裁牌、标点数、训一个只认这一桌的检测器」，再接到现有「候选 → 人工确认 → 账本」。公开权重和模板匹配都过不了：牌太小、重叠、和 BLACKJACK PAYS 印刷字混在一起。

本仓库不控制浏览器、不下注、不绕过受保护内容。
