# V0.3b 旁观录像：理解录像，不生产录像

日期：2026-09-12  
仓库：同一 `hakimiblackjack`，不另建仓库。  
基线：V0.3a 静态图候选 → 人工确认 → 现有账本。不重做 T9/T10，不改 SplitEngine / 公式 / 容差 / 5s / SQLite schema。

## 闭环

```text
现成 NVIDIA / Windows 录屏文件
  → 本软件打开、暂停、定位
  → 选择牌桌区域
  → 识别牌面与位置
  → 跨帧去重（同一物理牌只形成一个观察）
  → 人工确认／纠错／拒绝
  → 现有控制器与账本
  → 按当时可见信息复盘分析
```

录制由用户现有工具完成。本软件不开发录屏器、不控制浏览器、不连接账号、不自动下注、不把每一帧送给收费大模型。受保护内容导致录不到，当作输入限制，不做绕过。

## 观察者模式

记录庄家与桌上各玩家的**可见牌**。用户不必上桌。

| 能力 | 安排 |
|---|---|
| 看懂可见座位、识别并记录出现的牌 | 视觉模块目标 |
| 对选定座位给出操作 EV | 仅当现有分析模型支持该场景 |

现有分析在 `len(participants) != 1` 时返回 `SINGLE_PLAYER_ONLY`。能识别多人牌桌 ≠ 已能计算多人决策。未支持的分析必须标出，不得为了出数字而忽略其他玩家或套用单玩家模型。

识别与观察记录可以先交付。

## 三个准确性要求

### 1. 中途开始不能假装整靴

画面仍可识牌、跟踪、统计已观察部分。没看到之前发出的牌，就不能把剩余组成当成完整新靴。换靴画面也不自动补副数或烧牌数。

| 开靴声明 | 含义 | 对分析 |
|---|---|---|
| `full_new_shoe` | 从明确的新靴开始且观察完整 | 仍须人工确认副数与烧牌；不得默认 |
| `mid_shoe` | 从牌靴中途开始 | `start_from_new_shoe=False`，精确分析按现契约暂停 |
| `uncertain` | 起始条件不确定 | `start_from_new_shoe` 保持未知 |

### 2. 后面的画面可以确认牌，不能污染以前的判断

庄家底牌后来翻开：关联回同一物理牌，用 `reveal`，不二次扣牌。复算玩家此前决策时，当时未揭示的底牌仍是未知。账本已有历史前缀重放；视觉层必须分开保留：

- `video_time_ms`：录像内时间
- `first_seen_ms` / `first_seen_frame`：该物理牌首次出现
- `revealed_ms`：由牌背变为可见的录像时间（若有）
- `confirmed_at`：人工确认的墙上时钟，不得冒充拍摄时钟

### 3. 一张牌很多帧，只能记一次

| 情况 | 正确处理 |
|---|---|
| 同一张牌连续显示 | 一个观察，确认后只入账一次 |
| 连续两张相同牌面 | 两个观察，不按牌面去重 |
| 分牌导致原牌移动 | 更新归属，不当新发牌 |
| 遮挡、模糊、断帧 | 暂停确认或标记观察缺口 |
| 录像跳转、重复播放 | 已提交的 `observation_id` 不再写新事件 |

识别准确率高 ≠ 账本准确。验收对象是整段录像能否稳定还原成正确事件序列。

## 第一版范围

导入**一种固定牌桌样式**的本地录像：暂停、逐帧、牌面候选、座位／手牌归属、人工确认与纠错，接入现有账本。

暂不做：浏览器控制、账号连接、实时抓屏、自动下注、跨厂商布局、通用 OCR。

首批素材：牌面清晰、布局与缩放稳定，保留庄家及参与座位；账户／余额／聊天可遮去。先完整单轮，再含分牌的一轮，再长录像。原录像只读；裁剪与识别结果另存。

只处理有权使用的素材。`platform_claim = none`，直到另有授权样式。

## 与现有代码的衔接

- 入账仍只走 `ui.vision_bridge` → 控制器。`vision/` 不导入账本或求解器。
- 暗牌翻面走已有 `reveal`。
- 观察缺口走已有 `OBSERVATION_GAP` / `observation_status`，不发明新 SQLite 字段。
- 来源可用已有 `授权离线素材` / `识牌人工确认`。
- 静态图 V0.3a 仍可用。
