# V0.3e 识牌审查整改与验收边界

本轮从 `vision/v0.3c-live` 的 `fbff7b296532daa2eceea0c4d7893c0b0e37598f` 建立独立修复分支 `codex/v0.3e-recognition-review`。原素材、旧队列、模型和历史报告保留。数学引擎、DAS、事件结构和真实用户库未修改。当前为开发候选，未完成独立真实录像验收。

## 已核实的问题

- 同一局号在不同会话重用被误判为泄漏；现以 `(session, round_id)` 分组，并同时核验原帧内容、来源/局、裁片及已知物理牌身份。内部调参也沿这些身份分组。缺少物理牌标注的旧裁片数不能当成独立牌数。
- 旧评测只算已提取裁片，且把 junk 误收排除在条件准确率之外。现在另报全输出 precision、已提取裁片 recall、逐类混淆；缺图/解码失败保留分母并令评测不完整。真正漏检使用原帧框选真值评测。
- 真实开发帧上四个 Q 的连通块宽高比为 1.91–2.29，旧门槛 1.5 把它们提前过滤。人工原帧补框可绕过提取器，并保存框、方向、颜色、来源、物理牌 ID、漏检原因和标签来源。
- 实际 10 未出现预想的 1/0 分裂：一处因白牌边缘开口消失，另一处因宽48px超过46上限丢失。现在仅对牌体轮廓做3×3闭合，原墨迹保持不变，并把宽度上限调至52；该开发帧新增两个10角标，同时也新增两个负例。没有用这些改动声称 precision 提升。
- 原训练集中仅有的两条 `10` 是桌面印刷字 F，唯一 `A` 是非点数字形碎片。已保留原标签，并建立本机建议更正队列；建议更正与新增 Q/A/10 均为 `assistant_proposed`，没有冒充人审真值。这使旧类别计数和准确率的可信性进一步受限。
- kNN 原 top3 可能来自同一裁片的旋转增强；现在同一来源最多一票，margin 使用真正的其他类别近邻，并增加绝对相似度门槛。所有门槛只用训练内部验证选择，6/9 不接受无证据的倒置增强。
- 原模型未接入实时候选入口。现在图片、回放和捕获帧共用 `pipeline.recognize_loaded(adapter)`，模型/特征/提取器/训练摘要明确；切模型、来源、区域或新帧失败后旧候选失效。模型载入不授权自动确认。
- 旧 `label_glyphs ui --split` 保存时可能丢掉另一侧队列，已改为仅过滤视图、保存全队列。录像身份改用流式全文件 SHA256，避免长录像只比较前缀。
- 原视觉依赖同时安装 headless 和 GUI 两个 OpenCV 包，争用 `cv2`。现在新虚拟环境中固定一份 OpenCV，WGC 独立安装；不卸载用户已有依赖。

## 冻结开发对照

本机冻结 3374 个既有材料文件，共 513915783 字节。主要采集为 20 分钟、1825 个牌区帧；另有 30 秒烟测，不能据此当作独立最终测试会话。旧队列 617 个候选，196 个训练标签、63 个开发留出标签；其余未标。标签并无已完成用户复核的证据。

| 同一旧63裁片开发集 | 正确接受 | 错认 | junk误收 | 全输出precision | 正确/57可辨认裁片 |
|---|---:|---:|---:|---:|---:|
| 原模型本机复跑 | 37 | 9 | 1 | 78.7% | 64.9% |
| 固定196训练裁片，v3内容并票/拒识 | 24 | 1 | 0 | 96.0% | 42.1% |
| 建议更正3条并补8个原帧建议样本，v3 | 24 | 1 | 0 | 96.0% | 42.1% |

新逻辑更保守，同时降低了覆盖。这个对照既没有固定相同覆盖，也没有独立人审测试真值，不能称为整套识牌已变准。补 Q 的开发模型同样不能由不含 Q 真值的旧开发集证明 Q 识别能力。所有首次结果和后续开发结果分别保存于本机，未用后续报告覆盖旧结果。

## 原帧复核和录像转换

新增内容继续放在 `.local-evidence/`；原片、标签、模型、截图不入 Git。

```powershell
# 现有MP4等本地录像转标准会话，不另造录屏器；ROI为x0,y0,x1,y1
python scripts/video_to_material.py VIDEO.mp4 .local-evidence/new-session --interval 2 --roi 500,800,2350,1320
# 均匀抽取原帧，不展示模型预测，人工补框并确认整帧是否完整
python scripts/review_original_frames.py init .local-evidence/new-session .local-evidence/new-annotations.json --step 20
python scripts/review_original_frames.py ui .local-evidence/new-session .local-evidence/new-annotations.json
python scripts/review_original_frames.py queue .local-evidence/new-session .local-evidence/new-annotations.json .local-evidence/manual-queue
```

原帧 UI 支持选择已有框逐个确认或修正，不要求重画每个建议框。不同物理牌使用不同 ID，同牌跨帧沿用 ID；看不清的目标标 `unreadable`，不强贴点数。`complete` 只表示该抽样帧的全部目标已复核。固定间隔采样可能错过短暂出现的牌，不能代替连续视频逐帧验收。

```powershell
python scripts/train_rank_classifier.py --train-queue TRAIN_QUEUE --validation-queue TUNE_QUEUE --holdout-queue TEST_QUEUE --holdout-role final --output .local-evidence/new-training-run
python scripts/evaluate_original_frames.py SESSION ANNOTATIONS.json --model MODEL_DIR --layout LAYOUT.json --style-id STYLE_ID --output .local-evidence/new-frame-eval.json
```

训练可合并多个 `--train-queue`。旧63项应保留 development 身份；只有整来源隔离才允许指定 final，但这仍不等于通过最终验收。评测计入漏提取、错认、拒识、非牌/不可读误收、重复候选和有真值的归属错误。缺帧、未复核对象、不完整源使正式指标为 null。视频级去重、真实账本事件和轮次一致性未测时明确为 null。

已裁出的1850×520牌区可选 `blackjack_lab/vision/styles/navy_material_1850x520.json`，不会再套用旧小窗口裁剪；其中座位未标定，候选归属仍需人工指定。实际图片/录像/窗口操作见[指定模型与CLI](V0.3e-指定模型与CLI.md)。

## 验收状态

工程回归与真实效果分开记录。合成同帧离线/回放/实时入口一致、模型切换撤旧结果、临时 SQLite 40 帧确认两张同点数牌只扣两张等只证明工程契约。原分支全套测试本机复跑为 532 项、1 失败、2 跳过；失败为旧模板路径将合成 A 排为 Q，已修正模板与观测的归一化不一致。原失败日志保留。

最终测试、源码提交与 CI 身份见本轮交接记录。独立真实会话、全部目标人工真值、覆盖匹配下的准确性比较、连续视频物理牌/归属/轮次验收仍待完成。不得把源码推送、CI 绿灯或界面打开写成真实识牌验收通过。
