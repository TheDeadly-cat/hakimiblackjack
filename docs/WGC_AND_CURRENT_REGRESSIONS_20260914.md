# 实际窗口采集、当前回归与本机启动

本机已经运行旧／RGB 两条真实 WGC 识别路线，并完成当前版本的 A/A 分牌、同点数双牌、7/K 和小窗口检查。RGB 仍未达到替代旧前端的条件；本机启动器默认选择冻结的旧模型，可以在同一窗口选择 RGB 后重新播放。这里交付可运行的预览与失败对照，不宣称秒级正确识牌已经验收通过。

## 启动并检查

在本机仓库根目录双击 `Start_Realtime_Preview.cmd`。它打开新录像前 92 秒的真实 1 倍速预览，目标识别 8 FPS，结束后保留窗口；选择检测器或 FPS 后按“重新播放”才开始新一轮。橙色表示候选，绿色表示短时稳定，灰色表示待核／暂失；稳定值会过期。正式记账仍使用现有人工核对流程，这个演示不自动入账，也不输出可信座位归属。

该 CMD 已实际执行，并取得其自有预览窗口截图：源时刻 9.51 秒、已处理 69 帧，选择栏为旧提取器，底部模型摘要与冻结旧模型一致，候选和稳定值正在自动绘制。截图 SHA256 为 `4197d98ed09dac7c6521ee7236b56658d1cad5d5e8b40e1f3222b99762df645d`，对应 HWND 所有者 PID 64172。启动验证不等同于牌级正确性验证。记录保存在 `launcher-readback-1`。

启动器显式绑定本机已审模型、布局与录像，不按文件时间自动选最新模型，不自动下载文件。私有权重、视频、环境与布局不在 GitHub 中；另一台机器需要自行准备对应文件。等价 PowerShell 命令如下，从仓库根目录执行：

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
& '.\.local-evidence\rgb-corner-prototype\venv\Scripts\python.exe' scripts/realtime_preview.py `
  --video "$env:USERPROFILE\Videos\NVIDIA\Desktop\Desktop 2026.09.13 - 16.33.19.08.mp4" `
  --style '.local-evidence/continuous-review-20260913-21-12/runtime-inputs/style.json' `
  --model '.local-evidence/review-completion-20260913-003511/upright-training-run/model' `
  --detector '.local-evidence/rgb-corner-prototype/training-2-background' `
  --initial-method baseline --device cuda --fps 8 --last-frame 11040 `
  --evidence-limit 4096 --geometry 2000x1120+20+20
```

`--initial-method baseline` 在两种模型都加载时仍以旧方案启动；省略该选项保留原来的命令语义：显式传入 `--detector` 就先选 RGB。`--initial-method rgb` 必须同时指定检测器。只有旧方案时可以省略 `--detector`；无需加载 torch。实际窗口输入使用 `--window <已获准窗口的十进制 HWND>` 替换 `--video ...`，录像帧区间参数不用于 WGC。

本机为 Windows、Python 3.12.14、torch 2.11.0+cu128、torchvision 0.26.0+cu128、RTX 5060 8 GiB、CUDA 12.8、windows-capture 2.0.1。权重与许可边界见 [RGB 原型](RGB_CORNER_PROTOTYPE_20260913.md)。点数权重 SHA256 为 `b9fc805cf9a50aa8159f0718bcdcdee49722be7996a277537e1107adaf034be2`，RGB 权重为 `4e25bef9b2ff536e19be932201f084dffaa62cebbb2393d7a40fb737cf43d623`。

## 与事件验收的关系

### 额外稳定输出的原图反例

又检查了新录像 8 FPS 两轮中，所有“首次未匹配稳定轨迹状态”代表例的实际推理源帧：旧 31 例、RGB 18 例，共 49 例。它们来自已经冻结的运行，查看结果后没有改变模型或阈值。逐项图片与助手复核留在 `.local-evidence/realtime-r3-new-source/extra-stable-review-1/`，原参考和原评分不改写。

| 原图复核类别 | 旧方案 | RGB |
| --- | ---: | ---: |
| 桌布文字，被当作牌级稳定输出 | 17 | 0 |
| 应排除的倒置下角 | 0 | 9 |
| 正向上角，图中牌级与稳定值相符 | 9 | 8 |
| 牌级／方向仍未确定 | 5 | 1 |
| 首次未匹配稳定状态代表例合计 | 31 | 18 |

旧方案中多次将桌布 `INSURANCE` 的 A 或局部笔画误认为牌；RGB 在约 31–62 秒，将同一红 8 的倒置下角以多个预览 ID 稳定输出为 8。多次出现不是多个独立牌样本，9 次也不是 9 次正式重复记账。它们证明“稳定”不能排除系统性误收，且用户要求的“只识别正向上角、下半部分不重复识别”尚未全面满足。A/A 的 12 个下角检查没有误收，不能推广成其他牌也没有下角误收。

正向上角例说明“未匹配参考”也可能由位置／评分窗口缺口造成，不应自动算作假阳性。这里仅判断每个状态的首个代表源帧，不将其类别传播到整条轨迹、所有绘制或其他 FPS，不声称已经取得全输出 precision。6 个未决例继续保留未知。此补查由助手完成，不冒充用户复核或用于训练。

[新录像 5／8／10／15 FPS 事件对照](REALTIME_EVENT_MATRIX_20260913.md)仍保持原代码 `7b80f89`、原参考和原结果。8 FPS 下，31 个新可读目标的正确稳定已验证下界旧方案为 12/31、RGB 为 9/31；这次 WGC 成功运行不改变这些正确性结果，也不把快速错误算作秒级成功。
