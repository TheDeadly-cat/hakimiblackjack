# RC3 固定研究候选

当前功能冻结为已支持桌规下的手动记录、主注/逐座位条件比较、两手先补齐的 DAS、下轮固定策略估算、庄家 BJ 和两项边注。保持草稿，不合并 main，不创建 Release 或标签。

## 运行与身份

使用交付目录的新独立启动入口；原 RC2 入口和记录保持原样。运行副本只从已提交 Git 文件导出，`BUILD_INFO.json` 保存完整提交与源文件清单。启动入口先准备该副本的源码绑定数值程序，再打开独立试用数据库。源文件清单、实际模块加载路径及另行生成的数值程序/回执分别记录在交付清单中；不能用旧 main 的 CI 替代本候选。

运行副本应放在简短路径：Windows 旧版 .NET 编译器在过深的目录会报 CS1619，录牌仍可使用但数值不可用。本次深证据目录的失败回执保留，交付运行目录使用较短路径；未修改编译器、公式或系统设置。

## 使用变化

- 关闭时窗口显示收尾状态；若结果未保存，选择重试、返回处理，或明确放弃。不要用任务管理器终止来代替正常退出。已提交牌面与尚未保存分析分别处理；强制结束后的内存待保存结果没有恢复保证。
- 历史每页最多 100 条，按文件时间新到旧排列。列表只是未核验元数据；选中记录后显示完整核验结果。主注复算前再核对原数据库，开局/边注选择时即核对。仅导入单个历史文件不能伪造原数据库权限。
- 边注观察沿用原始两/三张牌及封存赔付；无关补牌不重复存同一观察，纠错、撤销或库存异常仍重新核对。历史复算始终另存。

## 完整资料备份

先正常退出并处理未保存结果，等待应用真正关闭，然后把整个研究资料目录复制到一个新的备份目录。若只使用“备份数据库”，它仍仅覆盖 SQLite。

完整资料必须包括数据库、同名 `.analysis`、`.opening`、`.sidebets`、`.deal_plans` 目录、`.sidebet-profile.json`、`.ui-preferences.json`，以及实际实验配置和输出目录中的 JSON/CSV。存在 `.startup` 启动回执时一并保留。源运行包和其 `BUILD_INFO.json` 单独保存。

恢复时复制到新的空目录，用同一候选打开恢复后的数据库，核对牌靴、轮次、剩余牌数、当前录入玩家/手牌。查看旧分析，核对原数据库后复算另存，再试录一张并检查旧文件摘要。不要在原备份上直接继续录入。

## 验收与性能边界

`fixtures/acceptance/responsiveness_v1.json` 冻结 6 副/1 人/剩 52、7 副/3 人/剩 65、8 副/7 人/剩 78 的切牌靴；越过切点后打完当前轮。`responsive_candidate_trial.py` 使用完整花色牌和独立结算真值，所有服务开启，记录队列、心跳、保存、数值完成、内存和文件增长；冒烟结果不冒充完整靴。`backup_restore_check.py` 实际运行实验并在新目录复算三类结果。`native_candidate_trial.py` 只准备独立数据和按键回执，原生输入交给 Computer Use 或操作者。

已有 3f4adfe 测量：代表性的 15 轮/185 事件/123 操作 p95 约 170ms（c2 约 239ms）；1k/5k/10k 多只短鞋合成事件的初始录牌 p95 约 255ms/1.15s/2.42s，仍未达到 150ms 目标，重放是主要剩余成本。不要将万事件单会话宣称为实时流畅；长数据保留供历史研究，日常试用使用独立会话/资料目录，不删除旧记录。5k 边注历史打开到首条核验约 230ms（原全列表核验约 23.6s），仅加载一页，不代表瞬间核验了全目录。

这些是指定机器与合成范围的实测，不保证任意设备或任意数据规模。手牌 5 秒、开局 20 秒和数学精度标准不变。当前固定提交是否完成全部长靴、原生操作、备份和 CI，须读取随交付保存的最终验收报告；本源码说明不预先签署未运行项目。
