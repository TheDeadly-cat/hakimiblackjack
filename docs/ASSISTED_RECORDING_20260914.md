# 辅助记牌工作台（开发验收版）

近期路线改为持续观察、候选草稿、人工确认、正式记账和随时纠错。本次保留现有模型、数学引擎及原来的静态识牌核对入口，没有训练或替换用户模型。

## 启动和使用

双击仓库根目录 `Start_Assisted_Recording.cmd`，或运行 `python -m blackjack_lab.main --quick`。普通主窗口的“悬浮记牌”按钮也能打开。先在主工作台核对规则、创建/恢复牌靴并选择本轮参与座位；悬浮条不会代替用户声明规则或观察完整性。

- 默认是可移动的 360×126 悬浮条。点击“展开”或 `Ctrl+Alt+Space` 打开 520×790 编辑面板；同一组合键或 Esc 收起。可改为列表中的其他组合键，注册失败/冲突会显示提示。
- 编辑面板获得焦点后，`2–9`、`0=10`、`A/J/Q/K` 修改当前草稿；Enter 确认。没有草稿时输入牌级会建立手动草稿。N 或“补牌”用于漏检补录。普通字母、数字、Enter 没有注册成全局热键，也不会转发给浏览器。
- 座位和分牌后的目标手始终显示。未分牌可沿用唯一手牌；出现多手时必须明确选手。草稿记住目标，后台新候选不会替换正在核对的那张。
- “上一张”或双击本轮牌记录打开修改；未知牌默认走“揭示原未知/暗牌”。改牌级、改归属和撤回重复牌必须填写依据。关联已有牌不会新增发牌；拒绝假检测不会写账本。
- 跨轮纠错：在主时间线选中发牌/揭示事件，点击“牌记录详细纠错”。面板显示原轮次与原牌。后续动作不成立时，整次修改被拒绝，需进一步修正后续记录。
- 在“识牌核对”选择既有样式、模型和本地录像/窗口，打开预览，再点“持续核对（采集不停）”。展开面板中同时显示持续画面、固定裁片、队列与已记手牌。
- 自动提示可关闭，保持画面和手动补牌。切换轮次后核对实际桌面，再点“绑定当前轮”；旧候选不会改绑到新轮。
- 停止、断流、来源身份/区域/模型变化会停止旧候选确认。录像结束后可以明确点击“转为录像复盘”，停止采集并在原上下文核对积压；此时明确标为复盘，不代表当前牌桌。窗口来源没有这个入口。
- 点击裁片或“原图”回看对应来源。连接有效来源时的手动补牌也会附当时整桌截图；未连接来源的纯手动记录会明确没有原图。

## 账本与证据

候选提取、跨帧显示和排队没有调用账本写入接口。每张确认草稿使用固定请求 ID，先验证完整重放、再保存 SQLite、最后发布状态。通知失败发生在保存之后时，按请求 ID 识别已经完成的提交，避免再次扣牌。

纠错使用追加 `CORRECTION`：原发牌 ID 和原事件保留，重放恢复错误牌的扣减并应用正确牌。新增了发牌的 `seat`、`hand_id`、`withdrawn` 修正字段；规则、牌靴、轮次和追踪身份不能借此改写。揭示事件跟随原发牌身份；纠正后来揭示的牌级时修改揭示事件，而非偷偷把该牌级提前到未知发牌时点。撤回有依赖揭示/动作的记录可能失败，这是需要进一步修正的矛盾，不会悄悄删除依赖。

当前分析由控制器提交通知立即失效。历史分析及 `through_seq` 前缀保留当时信息，后来的纠错不能改写过去保存的判断。

证据保存在所用数据库旁的 `.assisted` 目录，包含原预测、来源帧/裁片、媒体帧号/时刻、模型摘要、人工决定和提交意图/结果；PNG 摘要在确认前再次检查。恢复草稿时以实际账本事件判断是否提交，旧来源草稿仅供回看。此目录已加入 Git 忽略规则；记录不会直接进入训练集或改变权重。

## 队列与完整性边界

短时跟踪 ID 只用于抑制同一候选的重复排队，不是已经证实的物理牌身份。不同 ID 即使同为 Q 也不自动合并。遮挡后重新检测仍可能产生额外候选，需要人工关联或拒绝。排队上限为 64 张有效自动草稿，手动补录/纠错另保留空间；溢出提示观察缺口，不等于漏掉相同数量的物理牌。

显示的落后秒数是最早未处理候选自采集到现在的时间，不是完整牌桌账本已追上的证明。队列清空从不自动声明本轮完整。漏看一段无法补齐时，应登记观察缺口。当前补牌追加到记录序列；若漏牌应发生在更早的分牌/动作之前，需要先修复那段事件顺序，本版没有任意历史位置插入器。

来源帧 1.5 秒未到达或同一画面持续 3 秒会暂停确认。选定窗口的标题变化也会撤回当前来源；同一窗口内不改变标题的换桌无法被保证自动发现，仍须用户核对轮次并重新绑定。

## Windows 接口依据

全局呼出仅注册少量组合键，并带禁止长按重复的标志；没有全局确认热键或键盘钩子。见 [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。

悬浮条使用置顶工具窗口和不激活样式；编辑由明确操作激活，不启用鼠标穿透。见 [Extended Window Styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles)。

程序请求排除自有窗口被捕获，但是否有效取决于捕获路径，不能只凭 API 成功就声称通过。见 [SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。
