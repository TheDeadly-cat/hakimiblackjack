# T1 庄家 A 等待阶段与误按修复

庄家已明确非 BJ 后，测试输入十点底牌与已有事实矛盾。旧控制器把这个提交前可确定的牌面拒绝当作保存故障，暂停了录牌、撤回和分析。现在先在当前桌面的私有副本上验证揭示：这种误按返回普通输入拒绝，不保存十点，也不锁住 Back。真正的事务失败、回执未知及队列未执行仍保留原输入，不自动重试。

BCLC v2 完整八副新靴、零烧牌、所有初牌录齐且只有原始一张未知庄家底牌时，A 检查前立即启动评估。独立输入、结果和引擎身份保存“尚未记录非 BJ”。庄家 BJ 概率等于实际剩余十点牌占含未知底牌的剩余池比例；主注 EV 与净盈利概率混合 BJ 先结算和非 BJ 后策略两支。加倍或分牌尚未发生时，BJ 支只损失原始一注；玩家天然 BJ 对庄家 BJ 和局，对非 BJ 净赢 1.5。补牌与爆牌概率明确为“非 BJ 后实际补牌”的条件概率。

评估不会写入 PEEK_NEGATIVE，也不改变实际可操作状态。真正收到非 BJ 通知后的第一张玩家牌或 - / * 仍与该通知一次保存、一次 Back 撤回。检查前结果按原事件前缀复算，检查后信息不能替代原输入；原有结果格式与历史保存不变。未知牌靴、烧牌或不完整观察继续说明不可用原因。

用户确认原牌局实际非 BJ，十点只是找 bug 的测试。恢复时独立重放完整耐久前缀，核对失败记录的提交前后身份，并仅追加严格复核标记；原非 BJ 事件、原牌、失败原件和全部附属资料保留。具体资料与摘要只保存在本地验收档案。

本轮只做相关控制器、后台计算、完整结果保存校验、Tk 显示及最终 EXE 的定向验证。真实后台进程和有限八副数值引擎与模拟数值的 UI 测试分别记录。源码 CI、同入口安装、完整 Windows 验收和实时性能结论独立；原五秒计算预算未放宽，大历史实时性能仍未通过。继续更新同一 T1O3 和原 Draft PR，不自动合并。
