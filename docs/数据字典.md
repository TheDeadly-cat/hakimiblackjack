# 数据字典（V0.1）

对应开发大纲 3.1/3.2。所有分析结论必须能回溯到本字典中的原始事件。

## 1. 核心对象

| 对象 | 代码位置 | 说明 |
|---|---|---|
| RuleProfile | `core/rules.py` | 版本化桌规快照，建靴时锁定；改规则=新靴或纠错分支 |
| Session | `storage/database.py` | 一次录入会话；SQLite `sessions` 表 |
| ShoeState | `core/shoe.py` | 固定牌副数的牌靴组成账（13 牌面剩余 + 三类未知集合） |
| TableState | `core/table.py` | 一轮内的庄家/座位/手牌/动作状态机 |
| SeatState / HandInstance | `core/table.py` | `parent_id` 保存父子关系；`from_split` 同时标记分牌后的原手与新手，避免把原手21误算天然 BJ |
| Event | `ledger/events.py` | 只追加的审计事件（见第 3 节） |
| EventLedger | `ledger/ledger.py` | 可重放事件账本：去重、撤销、纠错、重放 |
| ReplayResult / ShoeSegment | `ledger/ledger.py` | 重放结果：每只牌靴一段，互不混入 |

## 2. 牌面取值

| 取值 | 含义 |
|---|---|
| `A,2,...,10,J,Q,K` | 13 种原始牌面（无大小王），永远保留，不被点值桶替代 |
| `T` | 已知是 10 点、但无法区分 10/J/Q/K（"10点未细分"），禁止捏造具体牌面 |
| `?`（UNKNOWN） | 牌面完全未知 |
| suit：`S/H/D/C` 或空 | 花色允许未知，不猜测 |

派生分组（仅展示，不替代原始牌面）：

- 小牌：2~6；中性牌：7~9；大牌：A、10/J/Q/K。
- "7:3"一类说法默认仅指大牌与小牌之间的比例，中性牌独立计数。

## 3. Event 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| event_id | str(uuid hex) | 全局唯一，相同ID与相同内容才幂等；冲突拒绝 |
| seq | int | 牌账本内单调递增，恢复时保留原序号 |
| etype | str | 事件类型，见第 4 节 |
| payload | json | 类型相关负载 |
| event_time / observed_at | float | 记录时间 / 实际观察时间 |
| session_id / shoe_id / round_id | str | 三级归属，自动补全 |
| source | str | 手动录入/导入/崩溃恢复/模拟器/授权素材等 |
| confirm_status | 已确认/候选待确认 | 候选牌不入确定性账 |
| evidence | str | 证据裁片引用（V0.3+ 使用，V0.1 为空） |
| rule_version | str | 新事件对应的规则快照版本；引擎版本由导出顶层 engine_version 单独保存。旧事件版本字段不改写 |

## 4. 事件类型与 payload

| etype | 关键 payload | 语义 |
|---|---|---|
| SESSION_STARTED | note | 会话开始 |
| SHOE_CREATED | shoe_id, n_decks, rules_snapshot(JSON) | 新牌靴并锁定规则快照 |
| ROUND_STARTED | round_id, round_no, participants | 新开一轮（不重置牌靴） |
| CARD_DEALT | seat, rank, suit, track_id, hand_id, face_state | 发牌；face_state=shown/hidden/unknown |
| CARD_REVEALED | target_event_id, seat, hand_id, rank, suit | 暗牌/未知牌揭示，不新扣牌 |
| PLAYER_ACTION | seat, hand_id, action, new_hand_id | 补/停/加倍/分牌/投降 |
| PEEK_NEGATIVE | — | 庄家已检查底牌且非 BJ（检查否定也是信息） |
| BURN_CARDS | count, note | 数量已知、牌面未知的烧牌 |
| OBSERVATION_GAP | reason | 观察缺口，牌靴级精确分析暂停 |
| ROUND_ENDED | settle, reason | true=要求完整结算且失败则拒绝写入；false=明确未结算结束；旧事件无此字段时尝试结算，信息不足则保留未结算 |
| SHOE_ENDED | — | 结束牌靴 |
| UNDO | target_event_id, reason | 令目标事件重放时失效，原事件保留 |
| CORRECTION | target_event_id, payload_fix, reason | 重放时以修正负载覆盖目标字段 |

`face_state` 三类与大纲 3.3 对应：

- `hidden`：规则性隐藏（庄家底牌）——物理离靴、牌面未知，计入 `unrevealed_out`；
- `unknown`：观察失败的未知牌——同上离靴，另计候选数，状态转"待核对"；
- 已知数量烧牌计入 `burn_unknown`；观察缺口只给不等式，物理剩余不可知。

## 5. ShoeState 数量账

| 字段 | 含义 |
|---|---|
| remaining[13] | 各原始牌面剩余张数（只被"已确认牌面"扣减） |
| exact_out[13] | 各原始牌面已确认移出张数 |
| t_bucket_out | 10 点未细分张数（只冲减大牌组，不冲减单一牌面） |
| unrevealed_out | 已发出但未揭示张数（含 hidden/unknown） |
| burn_unknown | 数量已知、牌面未知的烧牌张数 |
| gap / gap_notes | 观察缺口及原因 |
| pending_candidates | 待核对候选数 |

恒等式（无缺口时必须成立）：

```
总牌数(52×n) = Σ remaining + Σ exact_out ……（每牌面：初始=剩余+移出）
物理剩余 = 总牌数 - Σexact_out - t_bucket_out - unrevealed_out - burn_unknown
物理剩余 = Σremaining - t_bucket_out - unrevealed_out - burn_unknown
```

## 6. SQLite 表结构（`storage/database.py`）

- `meta(key,value)`：schema 版本等；
- `sessions(session_id PK, name, created_at, note)`；
- schema 2：`events(event_id PK, UNIQUE(session_id, seq), etype, payload_json, 时间戳与归属各列)`；
- 相同事件逐字段相同才跳过；序号或内容冲突报错。事件写入使用事务，完整导入整笔提交或回滚；
- 控制器先在副本预演、再提交 SQLite、最后发布内存状态。schema 1 先生成一致备份再进行事务迁移；
- `Card.event_id` 关联原始发牌事件，揭示按具体目标定位，不依赖牌面、花色或列表首个未知项。

## 7. 导出格式

- JSON：`format=hakimi-blackjack-lab-json`，含全部事件与每只牌靴的重放快照；
- CSV：UTF-8 BOM，新增 `event_json` 列保存完整身份/观察时间/证据/规则版本，支持往返导入；旧摘要 CSV 仅阅读；
- 任何演示/模拟数据必须在 `source` 字段标明，不与实盘记录混淆。
