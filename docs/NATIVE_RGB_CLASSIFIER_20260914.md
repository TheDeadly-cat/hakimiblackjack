# 原生 RGB 分类器：输入修正与未通过的对照

本轮完成了预训练 MobileNetV3 RGB 分类器与冻结掩膜 CNN 的实际对照。修正一次训练输入接线错误后，RGB 路线仍显著退步：同一 92 秒开发录像的正确稳定事件为 3/31，基线为 18/31。本轮权重不作为默认替代，不继续在这组结果上搜索阈值。

## 实际接入

`rank_rgb_cnn.py` 使用完整 MobileNetV3 Small 特征骨干及独立牌级头，1,002,670 参数，输入精确字符框的原生 RGB；等比例归一化到 64×64，白边补齐及 ImageNet 标准化，不经过 HSV/Otsu 二值掩膜。该尺寸变换不增加来源清晰度。模型输出仍是未校准分数，全部结果进入原有人工复核接口。

增加显式 `--rgb-classifier-model` 和 `--initial-method rgb-color`，与原生分块检测器共享同一检测权重。原启动器、默认模型及手动账本流程保留。模型使用摘要绑定的 NPZ，加载核对键、形状、数据类型、有限值、大小和身份，包含 BatchNorm 整数缓冲。加载不下载权重。

## 首次接线错误和更正

提交 `0e969780521ebf8eca00265dc327b5e083a0063e` 的第一次训练误把历史队列的 `crop_file` 当精确字符框。该字段实际是供人审的带周边画面缩略图，例如 75×68；框和实时输入却是 27×20。训练与实时输入因此不一致。第一次验证 14 正确、8 错认、167 拒识，实际录像 0/31 正确稳定，不能作为对齐输入后的 RGB 路线结论。这些失败和原模型均保留。

修正提交 `bd488c49de0bfd122c2162b6a663f595aec3980c` 增加 `prepare_native_rgb_queue.py`，从摘要核对后的原帧按既有审核框提取精确 RGB，同时保留标签、原始框、来源别名、物理身份字段和掩膜。四个派生队列均重新提取，原人审上下文图及原记录未覆盖。训练与裁片评估新增尺寸检查，审核缩略图不能再静默进入此通路。针对性检查覆盖源图改动拒绝、精确像素、标签来源保持、缺图保留分母、无掩膜接入及模型篡改拒绝。

本轮仍使用相同 296 个审核记录：190 牌级、106 杂项，源为 20:03；不是 296 张独立牌。已知不完整 K 框仍与冻结基线共有，没有同时扩框、换牌级或扩大训练源。这里比较的是预训练架构加 RGB 输入这条路线，不能把差异单独归因于颜色。

## 固定训练与历史诊断
