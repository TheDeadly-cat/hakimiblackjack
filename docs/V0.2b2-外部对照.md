## 1. 这次补的是什么

原始大纲和 `NOTICE.md` 一直把 `possibly-wrong/blackjack` 写成**候选交叉验证引擎**。此前完成的是审查我们的实现、仓库内独立参考、CI 和反例。那些不能代替外部项目在对齐输入后实跑。

本批只做语义能对齐的部分：

- 庄家终局分布（含 BJ 的原始分布，以及 A/T 非 BJ 检查后的条件分布）
- 未分牌停牌 / 补牌 / 加倍
- 6／7／8 副整靴，硬软手，普通暗牌与 peek，以及两种部分移除组成
- 三张牌硬 16：加倍必须因张数非法，不能靠一个待牌标志

分牌只记录、不作为门禁。`possibly-wrong` 的 CDZ-／CDP1／CDP 不等于我们“两手合计净收益、按新信息顺序决策”的目标。

## 3. 输入适配（必须先对齐，再比数字）

Hakimi 剩余计数：**含未知底牌，不含玩家可见牌，不含庄家明牌**。

possibly-wrong：

- `BJDealer::computeProbabilities(shoe)` 要求鞋里**仍包含明牌**
- `BJPlayer` 的鞋同样要让当前手牌和明牌在组成上仍然可能

转换：

```text
PW 牌靴[r] = Hakimi 剩余[r] + 玩家手牌中 r 的张数 + (明牌为 r ? 1 : 0)
Hakimi 剩余[r] = PW 牌靴[r] - 玩家手牌中 r 的张数 - (明牌为 r ? 1 : 0)
庄家-only：只加回明牌，不加玩家牌
```

规则对齐（研究模板 S17 / DOA / 软加倍 / 非 DAN / 无 DAS / SPL1 / 晚投降 / BJ 3:2）：

- 本批对 `strategy.exe` 回答 **CDZ=n、CDP1=y**。CDZ- 与 CDP1 只改变分牌后策略；未分牌停/补/加倍不用它。这样会跳过其 `compute_pdf`，否则整靴 PDF 会把对照拖成不可批处理。
- 双方动作 EV 都是**相对原始 1 单位注**；PW 再声明以“庄家非 BJ”为条件。A/T 时 Hakimi `peek_negative=true`。
- 庄家表是 `%.5lf`，门禁用 `6e-6`（原始）和 `1.5e-5`（peek 再归一化）。交互 EV 是百分数下 9 位小数，门禁 `1e-8`。
- 发现差异时先分：规则不同、策略不同、条件信息不同、还是实现错误。外部引擎不是自动标准答案，我们更复杂也不能当免责声明。

## 4. 怎么跑

```powershell
python scripts/fetch_possibly_wrong.py
python scripts/compare_possibly_wrong.py --output .local-evidence/external-pw-<唯一目录>
python -m unittest tests.test_external_pw_compare -v
```

`unittest` **不**调用 `strategy.exe`，只锁夹具、转换、解析和摘要。缺少二进制时对照脚本失败并提示先 fetch。CI 不下载 GPL 程序，也不把本对照当成 336 门禁。

夹具：`fixtures/v02b2/external_pw_cases.json`（66 条：庄家原始 20、peek 10、动作 36）。其中 3 条对子 8-8 的 **split** 字段为 `not_directly_comparable`。

每条回执含：双方输入、双方结果、钉住版本、牌靴转换、误差、可比较原因。回执写在调用者给的 `--output` 目录，默认应落在 gitignore 的 `.local-evidence/`。

## 6. 不能从这次对照推出的结论

- 不能证明 DAS / 两手顺序模型正确
- 不能证明我们采用了“最合适”的全部分牌实现
- 不能把 `strategy.exe` 的分牌 EV 当两手合计净收益的标准答案
- 不能把模拟器吞吐和精确有限牌靴求解比秒数

生产求解器与仓库内 Fraction 参考仍然可能共享同一错误假设；本对照的价值就是再增加一个**未抄入本仓库**的实现。

## 7. 另外两个项目：阶段边界

### T10 实验模块（V0.2c 最小入口已落地）

仓库现有 `blackjack_lab/experiments/`：合成场景与历史前缀回放共用 `EventLedger` + `build_input` + `calculate()`，不另写 EV 算法。

```powershell
python scripts/run_experiment.py --mode synthetic --decks 6,7,8 --player 10,6 --up 10 --output <新目录>
```

界面入口：主窗口「对照实验」。固定已知移除不是三/六轮模拟；超时和失败会写入结果，不只保留成功项。整轮策略模拟仍未做。

从 `AttackingOrDefending/Blackjack-Strategy-Simulator` 学到、仍适用的边界：

- 把“当前局面求动作”和“按某种策略做整轮实验”分成两个接口
- 非 BJ 检查后的下一张牌用条件概率，而不是把账面剩余直接当独立抽牌

从 `mhluska/blackjack-simulator` 学：

- 牌局环境发牌和执行规则，策略只根据可见信息选择，统计层流式汇总
- **不要**照搬其累计投注：作者源码仍标明 `betAmount` 未正确体现分牌和加倍

实验字段必须继续区分：原始注、追加注、整轮净收益、样本单位是轮还是手还是靴。AGPL 项目不并入产品。MIT 模拟器若只参考结构、不复制统计实现，许可风险较低，但仍要逐文件核对。

### V0.3 识牌样式基线（本批不做）

`EdjeElectronics/OpenCV-Playing-Card-Detector` 的价值是可检查的中间结果：灰度/阈值 → 轮廓 → 透视 → 角落 → 点数与花色 → 低于阈值则 Unknown。

首版仍应是：候选 → 人工确认 → 现有事件账本。识别成功不等于扣牌。跨帧去重、分牌移动、这张牌属于哪一手，都要另做。
