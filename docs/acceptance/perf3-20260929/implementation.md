# PERF-3 B：命令内复用与原子追加

普通录牌此前重复复制整本账本，组合动作还对所有旧事件逐条调用 `_insert`。
本改动在现有控制器入口内建立一个私有 CommandCandidate，沿用原 append 的事件赋值和校验逻辑，
每条新事件仍执行完整 replay；只复用本命令内已经验证过的中间状态，不保留跨命令状态缓存。

候选完全复制原账本，非法中间状态使候选失效，不能通过后加 undo 把非法步骤隐藏后继续提交。
提交前再次比较完整基线和新增事件的语义字段，防止预演后内容变动。
来源/证据允许由控制器补全，但仍经过数据库 Event 格式核验；既有事件任何字段都不能改写。
提交后发布的是普通 EventLedger，没有候选缓存或准备状态。

`LocalStore.append_validated` 在 `BEGIN IMMEDIATE` 取得写锁后读取并比较完整持久历史，再插入新增后缀。
完全相同的整个请求可重试且不重复写入；部分已存在、旧基线、会话/序号错误、全局 event_id 冲突均拒绝。
第 2/3 条写入失败由同一个 SQLite 事务全部回滚。没有新增 schema，也没有调整同步/耐久设置。
外部 `save_ledger` 仍走原完整导入校验路径。

计划摘要复用已有 PrefixSnapshot。该对象直接序列化为独立不可变字节，不先深复制一次相同内容。
提交后已验证状态和完整前缀可供同一个 read_frame 内的计划同步、通知及绘制使用；外层回调退出即清空。
新回调仍重新读取完整内容，同 seq 花色/原牌变动不能被版本缓存隐藏。撤回、纠错、会话切换也不跨回调缓存。

测试先于实现提交在 PR #35。新增追加接口测试进一步覆盖锁内核对、另一连接抢写被阻止、跨会话 ID 冲突、
同 ID 不同证据、精确批次重试、部分批次拒绝、预演后修改、历史 replay、非法中间状态及回调缓存释放。
原 7 个写入失败用例把注入点从旧包装方法移到真实 `_insert` 边界，业务断言保持不变。

仍有明确成本：每条新事件的完整 replay、命令基线全内容比较、SQLite 耐久提交和计划原子保存都保留。
本实现没有把这些同步工作隐藏到线程，也不声称任何规模已经达到 150ms/200ms 目标。
性能结论以同一冻结输入的新运行包复测为准；未达标将单独报告并提供后备设计。
