## 最小实施顺序

1. 一次命令只建一份完全隔离候选。仅在这个私有候选内复用已验证 replay；每次新增事件仍完整重放并检查中间状态。
   公共 append、导入、恢复保持严格；候选发生错误后不能带着半成品继续提交。
2. 已验证的本地新增后缀使用单一事务。`BEGIN IMMEDIATE` 后核对完整持久基线，才写新增事件；
   不再对既有千条历史逐条 `_insert`。完整基线不靠末序号推定；相同完整请求幂等，冲突/跨会话/部分提交拒绝。
   外部 `save_ledger` 全前缀验证不降级，SQLite schema 与耐久设置不变。
3. 复用已有不可变 PrefixSnapshot 与 read_frame。提交后计划、只读绘制可共享同一内容摘要与已验证状态，
   外层回调结束即释放；新回调重新读取完整内容，不能用 seq 代替内容身份。
4. 同输入复验。若支持规模仍超目标，保留实测失败并给出串行写入方案；本轮不盲目把共享控制器/连接搬到线程。

## 修改前契约结果

新增 12 项真实 SQLite 控制器契约通过，覆盖单事件、自动暗牌、自动开轮、换靴、整组撤回的事务中途失败，
计划保存失败、提交后通知失败、非法中间状态、事件幂等/冲突/别名及同 seq 花色变化。
最初一次测试配置漏传 deal_direction 导致 3 个错误，已保留原日志；修正测试配置后 12 项通过。
失败注入位于实际 `_insert` 边界，后续换入口不会绕过此验证。

这不是最终验收。录牌 p95 ≤150ms、心跳 p99 ≤200ms 仍是原 fixture 的期望目标；
正确性通过与速度达标将分别报告，旧 RC3 的 CI/人工按键不冒充新提交验收。
