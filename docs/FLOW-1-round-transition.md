# FLOW-1：阶段操作与同靴下一轮

小面板固定位置显示当前流程和明确命令。初始发牌、实际非BJ检查、玩家操作、庄家录牌、可结算、需核对分别显示对应操作；牌面键的位置不被收尾按钮替换。常见动作不可用时显示已有规则原因。

可结算时点击“确认完整并下一轮”，表示操作者确认本轮移出的牌已录全。控制器先验证本轮结算和下一轮设置，再以一次 SQLite 事务追加 ROUND_ENDED、ROUND_STARTED；不会刷新牌靴或确认新轮非BJ。按钮绑定原轮次，连点/旧回调不能重复收尾。任一数据库写入失败，两条事件都不提交；计划文件失败时两条已提交事件保留，录入暂停并提示核对。

结果以非阻塞摘要显示，点击可展开。次级“只结算”仍保留；换靴通过原工作台独立操作。撤销仍逐事件进行（先撤新轮开始，再撤结算），不改原有审计规则。恢复/刷新从账本读取摘要，不写业务事件。

`tests/test_daily_flow.py` 验证一次收尾、同靴数量、重复回调、第二次插入失败和重试、下一轮设置失败、旁路计划失败恢复、两种录入方式状态一致、阶段门禁和只结算。既有暗牌、概率与键位回归仍保留。没有改概率公式、核心桌规、SQLite 表结构，也不把建议当作实际动作。
