## 4. 开发过程中真实出现并修复的失败（不以最终通过掩盖过程）

首轮 58 个测试中曾出现 3 failures / 11 errors，均为真实缺陷，修复后复跑通过：

1. 守恒公式漏减未揭示牌与烧牌 → 修正 `ShoeState.conservation_check`；
2. 暗牌发牌未指定 hand_id，揭示事件重放时定位不到手牌 → 重放内增加
   发牌事件→解析 hand_id 的映射；
3. 分牌动作的新手牌 id 只在重放中产生、落账事件缺失 → 落账前预演补写 new_hand_id；
4. 庄家信息不全时 ROUND_ENDED 直接抛错导致整个账本不可重放 →
   账本层容忍"已结束未结算"，界面层仍坚持先补信息再精确结算；
5. 两处测试断言本身写错（未知牌点值、大牌组扣减计数），已按正确口径改正。

3. 结算为按已录牌面的确定性记账，不含庄家补牌策略推演；

5. 未做跨平台验证（按大纲 Windows 优先；macOS/Linux 理论可用但未验收）；
6. 未接入 possibly-wrong/blackjack（GPL-3.0）等任何第三方代码，见 NOTICE.md。
