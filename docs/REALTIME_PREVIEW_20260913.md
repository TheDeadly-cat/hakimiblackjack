# 单一布局实时预览进展

现有识牌核对窗口新增“1倍速实时预览”。选择本地录像、归一化布局样式及明确的点数模型后，后台持续识别，界面自动叠加候选与短时稳定值。可选择 5、8、10、15 FPS 重新播放并保存本轮记录。正式入账仍通过原人工流程。

当前检测仍是 `navy-components-border-3 + upper-upright-local-2`，点数模型权重和拒识门槛未改变。直接 RGB 检测方案尚未接入，本文不是完整任务验收。

## 已接通的行为

- 复用 `VideoReader`、`FrameIntake.latest()` 及一份不消费识别队列的最新预览帧。顺序播放跳过的源帧、入口采样丢帧及队列丢帧分别保留。
- 一个后台识别线程、一个常驻模型；界面不等待账本或分析计算。运行记录只保留有界元数据，不累计全尺寸图像。
- 单调时钟记录取帧、预处理、检测、分类、关联、候选就绪、Tk 显示提交。显示提交不是屏幕硬件扫描时刻，也不是从首次可读事件开始的正确识别延迟。
- 预览关联使用局部图像、短时速度预测和一对一分配，不把点数加入关联代价。歧义匹配及超时关联会撤回。旧人工账本跟踪器保留。
- 连续有效样本达到支持数和时间跨度后产生稳定值。单帧点数冲突会标注；持续冲突撤回稳定值。稳定支持超过 550 ms 或身份超过 650 ms 未更新会失效，冻结画面重复读取不增加支持。
- 预览身份只在本轮运行内有效，不宣称已经证明物理牌身份或座位归属。最多保留 96 条轨迹，每条最多 8 个短时支持。

顺序解码接收 414 帧，队列跳过 185 帧；更高接帧数量没有被宣称为更高点数正确率。20 个指定源帧的新旧读取 RGB 摘要一致，读取耗时约 3.18 s → 0.89 s。三个表中运行均未报告识别线程错误。早期第一次窗口截图在自动关闭后才查找窗口，未捕获到；后续独立运行成功取得自有窗口图像，该首次尝试仍保留。

实际原图、完整计时和窗口截图保存在忽略目录 `.local-evidence/realtime-r0-20260913/`、`.local-evidence/realtime-r2-20260913/`。这些开发片段没有完整的逐事件真值；稳定显示次数不是正确牌数，不能据此报告“一秒内稳定认对率”。
