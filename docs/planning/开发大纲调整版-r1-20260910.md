## 1. 产品目标：记录是输入，分析辅助才是主要价值

最终链路：

手动输入 / 自建或授权素材识牌
→ 确认牌与动作事件
→ 维护牌靴、牌局和当时可见信息
→ 概率、合法动作EV、整轮净收益分析
→ 中文展示与人工决策
→ 保存当时分析并复盘。

不改变：Windows优先、本地优先、6/7/8副、庄家与最多7位玩家记录、未知信息不捏造、人工掌握操作、默认不上传画面、不接真实资金账户、不自动下注、不绕过捕获限制。

七副仍是研究与兼容配置，不据此声称某平台已存在七副牌桌。概率值必须来自经过验证的计算程序，不由大模型口头编造。动作EV较高不等于已证明开局有正优势，也不等于应提高注额。

## 2. 本次关键调整

旧顺序的问题是：把完整可靠性治理、较大规模性能、界面整理和外部分发验证全部放在前面，最后才安排V0.2，而且只写设计。

改为两条相互配合的工作线：

- 主线：数学契约与独立基准 → 概率与单手EV实现 → 最小中文分析面板 → 历史复盘 → 分牌/整轮分析与实验。
- 修复线：核心错误与必要数据保护 → 测试验证 → 为集成分析版提供可用输入。

两条线可以从冻结快照接口后并行。没有多名执行者时，先完成接口与必要修复，随后把主要实现工作转向数学闭环；不得同时开展大规模UI重写、识别模型和捕获工程。

“允许开始数学开发”不等于“允许使用未修复记录输出正式分析”。独立算法可以先用合成快照；集成发布必须通过它实际依赖的正确性、信息隔离和数据保护门槛。

## 4. V0.2a：第一版实际分析能力的明确范围

### 4.1 必须交付

1. 三种副数都能通过同一计算路径，不只把6/7/8做成界面选项。
2. 下一次目标抽牌的点值分布，以及补一张后的爆牌概率。
3. 庄家终局分布，明确采用的规则、底牌条件和检查信息。
4. 停牌、补牌、加倍，以及已确认支持的投降条件下的EV；无此合法动作时显示不适用。
5. 对每项结果标注可用/不适用/未支持/待核对/计算中/超时/过期。
6. 中文界面显示真实计算值、适用前提、EV单位、支持范围和结果时点。
7. 保存分析快照和计算身份；按同一事件前缀可以复算或读取原始分析。
8. 提交独立正确性验证、实际命令和结果、目标机器性能记录。

补牌EV必须包含该动作之后按明确策略继续操作的结果，不得把“再抽一张后强制停牌”偷偷作为通用补牌EV。首版可规定补牌后在剩余合法的补/停动作中按当前可见信息重新决策。

### 4.2 默认验收模板：研究模板，不冒充任何平台桌规

为减少无边界组合，建议先冻结一套研究模板：

- 有限不放回，完整新靴开始，已知烧牌数量为0，无观察缺口。
- 6/7/8副分别验收。
- 庄家S17、天然Blackjack净赔付3:2。
- 美式底牌：庄家明牌A或十点时，进入该模板玩家决策前已有明确非BJ检查；其他明牌按模板处理。
- 初始两张牌可加倍，加倍后仅补一张。
- 首版可纳入明确的晚投降；必须确认它在当前状态下合法。
- 规则档案可以包含分牌规则，但V0.2a不承诺分牌EV。
- 当前轮EV先承诺一个参与玩家、一个尚未分牌的目标手牌。已有7座位录牌不删除，多玩家EV另行验收。

以上是建议的验收起点，必须通过选择“研究模板”或明确核实后使用。实际桌规不同不能强行映射成这套模板。其他规则可以记录，但相关分析应明确阻止；不能因为原记录表单支持某值就认为算法已支持。

H17、6:5、已知非零烧牌、其他底牌时机等扩展可以提前实现，但每项必须有独立验收，不得为了赶进度静默混入主矩阵。

### 4.3 不完整动作集合的展示规则

必须分别计算：
- 当前真实桌规下的合法动作集合；
- 引擎已经支持且完成计算的动作集合。

如果分牌合法，但分牌EV尚未实现，可以展示“已计算动作的部分比较”，必须显著说明分牌缺失，并禁止标注“全局最优”“最佳动作”或唯一高亮推荐。已经分牌的场景在未支持前不输出伪精确结果。

只有当前状态的全部合法动作均被计算，且数值误差/近似误差足以区分时，才允许显示“在所声明模型与信息条件下EV最高”。全部动作EV为负时，只能说明较高EV可能意味着少亏，不将其转换为开局正优势或注额建议。

### 4.4 不能误删的未知信息支持

正常未揭示庄家底牌是模型需要处理的隐藏变量，不是V0.2a应一律拒绝的输入。否则多数正常决策时点无法分析。

- 保存“物理已离靴但未获知牌面”和“物理仍待发”的区别。
- 必须处理已知非BJ检查对底牌候选的约束，以及它对后续抽牌条件概率的影响。
- 不能将账面remaining直接除以physical_remaining当作通用分布。
- 不可通过先假定看见底牌、针对每种底牌选择最优动作、再平均结果的方式计算玩家策略。
- 在每个玩家决策节点，应对当时未知的情形进行条件期望比较；只有真实可见的新牌才允许更新决策信息。
- 数量未知的烧牌、漏录、来源断流、未知起靴属于另外的问题，应停止相应精确牌靴分析。
- 已知数量但未知牌面的烧牌仍可作为后续明确模型扩展；不要永久等同于数量未知的缺口。

## 5. 最小技术实现方向

保留原来的Python/Tkinter/SQLite、core、ledger、storage、ui。下列文件名是拟新增/拟拆分建议，不是当前存在的实现声明。

| 建议位置 | 责任 |
|---|---|
| analysis/contracts.py | AnalysisInput/Result及状态、范围、版本、错误码 |
| analysis/information.py | 从事件前缀建立仅当时可见的信息状态；隐藏变量与分析资格 |
| analysis/probability.py | 下一次抽牌、补牌爆牌和庄家终局概率 |
| analysis/actions.py | 已验收动作的EV及续玩策略 |
| analysis/service.py | 一次分析请求、取消、超时、身份匹配与结果发布 |
| simulator/reference.py或tests内参考模块 | 与优化路径独立的小状态枚举、验证环境 |
| ui内局部分析组件 | 当前目标、概率/EV、计算状态、部分覆盖、历史结果 |
| storage下结果旁路存储 | 保存分析快照，不改变原始事件审计语义 |

### 5.1 输入快照至少包含

session_id、shoe_id、round_id、through_seq、目标seat/hand_id、规则内容与摘要、已确认移除与未知信息、底牌/检查状态、合法动作条件、策略版本、引擎版本、输入摘要、支持范围。

不得向分析服务传入模拟器完整牌序、未来事件或未来揭示。缓存键使用规则内容摘要，不只使用可能重复的规则版本号。任何字段影响结果时，都必须进入输入身份或关联到不可变快照。

### 5.2 输出至少包含

状态、原因码、输入摘要、事件前缀、规则/引擎/策略版本、已计算动作、未支持动作、各动作EV、概率分布、EV单位、精确或近似标识、近似方式、耗时；模拟结果还应包括样本量、种子与误差说明。

EV统一采用相对该次决策所属原始一单位初始注的整手/整轮最终净收益口径，返还本金不算盈利。若另显示从当前时点算起的增量价值，必须用另一明确字段，不能混合比较。

### 5.3 计算和界面

先做独立小状态精确枚举参考，再实现有缓存的递归/动态规划或经过论证的其他求解方案。不要先换语言或引入外部服务。是否需要工作进程，由实际计算耗时决定；UI的取消与过期保护从第一版具备。

每次计算绑定request_id和输入摘要。牌面、规则、目标或会话改变后，旧结果立即失去“当前”资格。较早请求晚返回时不能覆盖较新快照。超时不能用上一局结果代替。

建议V0.2a初验目标：冻结目标Windows机器后，对规定场景实测；典型单手请求p95不超过2秒，5秒预算到期明确显示超时并可继续录入。数值仅是建议验收目标，不是当前性能结论。若达不到，提交实测与局部优化方案，不静默降低精度。

### 5.4 数据保存与兼容

优先继续原事件schema 2，不为分析结果建设通用迁移框架。首版结果可使用独立目录中的版本化JSON旁路文件，采用安全原子写入、内容摘要与事件前缀关联。结果写失败不修改或回滚已经提交的牌面事件。

原始事件是事实来源；分析结果是派生数据，但原始历史分析也不能被新引擎结果覆盖。新引擎重算应创建新的结果身份，明确与当时已存结果不同。

旧非法记录允许只读诊断、原样导出，未经纠正与验证不能作为正式分析输入。未核实的数据不得因为分析新增而自动变成“已确认”。

- 测试：契约字段与非法状态样例；不要求重新审查全仓库。

### T1：必要数据正确性与保护修复
- 目标：修复原审查F01—F06中仍存在且影响启用路径的问题，补齐未知输入门槛。
- 涉及：core/table.py、ledger、storage、controller、相关UI回调和测试。

### T3：概率与常见单手EV
- 目标：输出实际概率和停/补/加倍/支持的投降EV，不止写接口或静态表。

- 风险：错误的续玩策略、遗漏追加额、对未知底牌先分别最优再平均。

### T4：中文分析面板与请求生命周期
- 目标：录入后可以看到真实结果及其前提，而非在后台孤立运行。
- 涉及：analysis/service.py、ui内局部组件、controller。
- 依赖：T2接口冻结后可开发；T3完成后接入真实引擎；T1是集成发布前置。
- 完成：计算/失败/超时/过期/部分支持状态齐全；目标切换结果不串局；不需要重做整个界面。
- 测试：真实Tk回调；较旧计算晚返回；正在计算时撤销/纠错/换靴；所有EV为负；有未计算合法动作。
- 风险：旧结果冒充新结果、视觉上错误暗示盈利。

### T5：结果快照、历史复算与发布验收
- 目标：保存结果、按前缀复算、产出实际交付证据。
- 涉及：storage结果旁路、历史UI、scripts/verify_release.py、CI、README。
- 依赖：T1—T4。
- 完成：同一输入与版本可复算；新版重算另存；Windows目标路径跑通；唯一证据目录含commit/命令/退出码/环境。
- 测试：断网、重启恢复、旧格式诊断、结果写失败、历史未来隔离、约定计算时延、取消。
- 风险：覆盖历史分析、只报测试数量不核实结果。

首批PR建议：
1. 契约、快照和独立数学参考（合成场景，不开放未验收分析）。
2. 必要记录/结算修复与数据保护（体积过大可拆两PR，但不是八项治理串行前置）。
3. 概率与单手EV核心和独立验证。
4. 中文面板、结果生命周期、快照复盘与目标环境验收。

PR1与PR2可并行；PR3可在PR1基础开发；集成版发布必须在PR2相关项通过后。每个PR持续测试，不把测试全部留到最后。

## 8. 验收矩阵：下一版必须有新能力，也必须算对

以下是拟定验收要求，不是本轮测试执行结果。

| 编号 | 场景 | 可验证结果 |
|---|---|---|
| A01 | 相同算法分别接受6/7/8副研究模板 | 使用对应初始化与剩余计数，输出实际概率/EV，不把副数仅作为标签 |
| A02 | 非配对单手，停/补/加倍均合法 | 每个支持动作有实际计算EV、单位、策略与快照身份 |
| A03 | 补牌后仍可继续补或停 | 按已声明的后续可见信息策略求值，不偷换为强制停 |
| A04 | 正常庄家底牌未知 | 在支持模板内仍能分析，不读取真实底牌 |
| A05 | 增加明确非BJ检查信息 | 底牌约束进入计算；与独立参考一致 |
| A06 | 改变未来底牌与牌序但保持当前可见信息相同 | 事前输入和策略不变；固定设置下分析结果保持相同 |
| A07 | 一个小状态中不同隐藏牌分别偏好不同动作 | 求解器按当前信息选择，不能得到偷看底牌才有的期望收益 |
| A08 | 每个声明完成的终局分布 | 概率非负且归一；EV与同一收益分布反算一致 |
| A09 | 当前可以分牌，但分牌EV尚未实现 | 显示部分比较、分牌未支持；不显示全局最优推荐 |
| A10 | 未支持桌规、漏牌、未知起靴、非法事件 | 不输出相应精确分析，明确字段/原因 |
| A11 | 所有动作EV都为负 | 不显示正优势、应加注或盈利保证 |
| A12 | 新牌/撤销/纠错/换目标在计算中发生 | 老结果立即过期；老请求晚返回不覆盖当前结果 |
| A13 | 计算预算用尽 | 明确超时/未完成，可继续录入；不拿上次结果充数 |
| A14 | 保存结果后重启，再按同一前缀查看 | 能识别原结果与引擎版本；重算不覆盖原结果 |
| A15 | 存储写失败与UI刷新失败分别注入 | 清楚区分事件未提交和已提交；不诱导重复扣牌 |
| A16 | 导出到活动库/写到一半失败 | 活动库受保护；原导出不被截断 |
| A17 | 原三项规则缺陷及合法对照 | 缺陷回归通过；合法再分A、正常终局不被破坏 |
| A18 | 独立枚举与生产求解器 | 使用不同实现思路；不共同依赖同一被测结算函数当标准答案。仓库内参考不能代替外部引擎实跑；T9-H3 钉住 possibly-wrong/blackjack v7.6 做庄家分布与未分牌动作差分，见 `docs/V0.2b2-外部对照.md` |
| A19 | 固定种子的模拟交叉检查 | 提供样本量、误差方法和独立采样单位；不把蒙特卡洛随机输出要求成逐位精确相同 |
| A20 | 指定Windows机器的场景集 | 提交p50/p95/最大耗时与资源数据；阈值按已冻结目标验收 |

小状态精确参考建议优先用有理数；浮点生产结果的初始验收建议采用预先规定的绝对误差（例如1e-10），实际阈值需随算法与状态规模评审，不得看见结果后任意放宽。模拟与精确结果分别标注，不能把概率和为1当作数学正确性的充分证据。

## 9. V0.2b/c与识别捕获的衔接

### V0.2b：补齐有声明边界的完整动作比较

在选定模板内加入分牌、再分牌、分A限制、DAS与追加注处理。整轮净收益合并所有子手，以原始一单位初始注为基准；共享牌靴、共享庄家和动作顺序必须进入模型。

对完整净收益分布，不能把分牌子手胜率当成互相独立的结果直接组合。存在近似时明确策略、误差和未覆盖部分。所选桌规允许4手时，不得只计算2手上限却将结果标为该桌规精确最优。

H17/6:5/已知数量烧牌/其他底牌机制等按规则逐项验收。除非明确覆盖并通过测试，不承诺任意规则笛卡尔积。

### V0.2c：恢复原始研究问题的可执行实验

比较6/7/8副、1～7玩家、前三轮与前六轮后的组成与结果。必须给定座位顺序、其他玩家策略、完整规则、随机种子和实验单位。实验接口应把“求当前动作”与“按策略跑整轮”分开；统计单位区分轮／手／牌靴，原始注、追加注和整轮净收益分列。模拟器的累计投注字段不得在未核对分牌/加倍口径前照搬。识牌（V0.3）另用可检查的中间结果和人工确认，识别候选不直接扣牌。详见 `docs/V0.2b2-外部对照.md` 第 7 节。

固定移除65/130张是构造场景，不等于三/六轮必然发出的牌数。“大:小=7:3”不是完整牌靴组成，需单列中性牌和组内牌面分布。记录每轮/每靴关联，不把同轮七名玩家当成七个独立样本估计误差。

当前已发手牌的动作EV与尚未发牌时的开局优势分开，下注金额优化不随实验模块自动加入。

### V0.3/V0.4：提前准备数据，不提前扩成庞大识别工程

数学开发时可并行整理一种自建或授权样式的截图/视频标注与候选事件接口，不依赖完整EV才能做素材准备。

第一版识别使用人工确认后提交事件，同一账本再触发同一分析；不让识别模块直接改牌靴或计算收益。先证明不漏、不重复、可纠错，再逐步提高自动接受覆盖。

授权捕获随后接入，断流/最小化/黑屏/缩放时必须停用过期分析，不绕过系统或平台限制。某平台的当前许可与可接入性需另行核对，本路线不作许可结论。

## 10. 暂缓项和AI分工

暂缓：完整UI换栈、无证据的大规模缓存/增量事件引擎、多用户/微服务/云同步、跨厂商通用识别、旁注、注额优化和追损、自动下注、完整安装升级系统。

基本可读性、关键布局、真实数据保护、信息隔离和正确性测试不是暂缓项。

核心规则、数学模型、架构和最终验收由主模型/经验证的同级技术负责人掌握。辅助模型可做范围明确的样本整理、测试执行和简单实现，不因省token让未经验证的模型接管项目或降低核心计算质量。
