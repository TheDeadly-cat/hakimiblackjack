# T1 BCLC 日常录牌修复

本轮按用户明确的日常录法修复，不新增桌规或计算模型。此前 BCLC 保存的 `simple_hole=False` 使起手牌录齐后仍要求点“底牌已发”；完整新靴和烧牌观察一直为空，主注分析返回 `START_UNKNOWN`；小面板又隐藏不可用的 EV 行。庄家 A 阶段原来的键路由把非十点也送去揭示底牌，玩家动作则被检查阶段阻挡。

日常“新建牌靴”以用户声明的完整 8 副、初始烧牌 0 记录观察事实。导入、底层控制器及未确认的旧牌靴仍保留 UNKNOWN。当前靴补事实用追加 `CORRECTION`，只允许将三个观察字段补为 True / True / 0，不能更改其他桌规、牌副数、原建靴事件或已录牌。保存后保留已认证的录牌位置。若它尚是最后一步，撤回标签明确写“撤销新靴事实确认”；继续录牌后的 Back 撤销刚录的牌。

BCLC v2 新模式默认自动登记未知底牌存在，仅 A 明牌等待实际 BJ 通知。按用户指定约定，A 阶段 0 / J / Q / K（以及原有 T）揭示实际庄家 BJ；其他点值或合法 - / / / * 输入实际第一位未完成玩家的牌或停牌、分牌、加倍，同时记录已经收到非 BJ 通知。这两个事件一次事务保存，一次 Back 一起撤回并恢复 A 等待位置。原底牌的点值始终未知，直至真正揭示；草案桌规和手动揭示入口不套用此路由。

EV第1、EV第2、净盈利概率保留显示位置。待计算或不可用时清空数值并显示原始原因，取消、保存暂停和录牌变化不会保留旧建议。概率为最终净额大于 0 的概率；补牌爆牌率使用同次已有计算结果。多人计算仍明确采用“其他玩家之后不再补牌”的条件，实际已发牌全部保留。21 点、已爆牌或合法动作不足时不能制造两项建议。

小面板 A 阶段显示操作快捷说明，并根据非 BJ 后第一有效玩家的只读预演显示合法按钮。默认停用的两项边注文案隐藏，保留旧边注配置与历史。键映射 J/Q/K 合并为十点；拼音输入法的字母组合仍可能截获字母，数字 0 是相同的十点输入。

定向验证覆盖实际 Tk 键路由、事务失败、非法动作拒绝、整次撤回和恢复、UNKNOWN 与明确新靴的分析差别、真实引擎 EV/概率显示及原小窗口布局。源码检查与最终 EXE 检查分开记录；本轮没有重新执行全套测试或大历史性能验收，不将本次修复称为实时性能已通过或正式发布。继续更新原 Draft PR 和 T1O3 入口，不自动合并。
