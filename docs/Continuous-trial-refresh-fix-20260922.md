# 连续试用发现的重复刷新开销

在独立八副牌模拟靴连续录入到约300条事件时，单命令耗时逐渐上升到约1.3秒。用固定367条事件前缀诊断，一次 refresh_all 经多处视图通知调用了49次完整重放；该次 cProfile 样本约0.905秒。此前的部分演练已保留并标为因已验证性能问题中断，不算作完成的牌靴。

修复只在一次只读绘制期间共享回放快照，绘制结束或异常时清除；若绘制中发生提交，按真实控制器上下文重新读取。控制器 state()、写入预演、数据库事务和分析输入构造均保留独立权威重放。没有跨操作长期缓存，没有改变牌局或计算结果。

同一367条事件前缀复测，完整重放降到3次，该次 cProfile 样本约0.103秒。它是一个可复现的局部性能对照，不代表真人跟牌速度或所有长会话的性能保证。`tests/test_view_frame.py` 覆盖绘制无写入、提交/纠错/撤销时重新读取、嵌套绘制和异常清理；旧的过期结果保护测试继续执行。

固定试用候选还包含庄家键盘未松开时内部焦点变化的重复录入修复。两个问题都来自具体输入/连续使用证据，未增加新的面板功能。下一步在新的固定运行副本中重新完成三靴演练，报告需区分独立模拟演练与真人持续使用反馈。
