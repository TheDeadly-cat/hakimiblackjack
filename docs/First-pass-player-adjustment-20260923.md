# 第一遍发牌时调整本轮人数

用户在第一遍发牌时就能发现人数开错。简洁面板右上角在此阶段显示“本轮 N 人”，加减按钮直接作用于正在记录的这一轮；不必结束这一轮，也不用逐张撤销重录。

- 开了7人，已经输入前6位玩家各一张，减为6人：6张牌顺序和点数保留，下一张直接给庄家，无额外确认框。
- 若已经把实际庄家明牌输入到了玩家7：预览明确显示“第7张：玩家7 → 庄家”，确认后调整归属。
- 开了6人，第一遍发现其实有7人：加为7人，已经录下的顺序保留；误记为庄家明牌的第7张会在预览中移给玩家7，下一张给庄家。
- 操作仍支持1至7人、正序与反序。Space暂停状态保留。移除本人座位时预览会说明新的本人分析座位。

这里“第一遍”包括全部参与玩家第一张和庄家明牌。在开始录第二遍、记录动作、人工跳位或出现未对齐记录后，按钮恢复显示“下一轮 N 人”，保持原来的下轮设置行为。这次按用户澄清处理第一遍发现人数错误，不承诺自动重排已经发生分牌、补牌或结算的牌局。

记录采用现有追加式撤销与替代事件：先在内存完整预演，再在同一个SQLite事务中保存；原始事件逐字保留，替代牌保留原观察时间、来源及原事件引用。轮次号不增加，牌靴不重置。发牌计划只在数据库提交后发布，并重新绑定完整前缀。事务失败时人数、牌、原计划均不变；旁路计划保存失败时保留已提交修改并暂停，避免要求重新输入已保存牌。

若人数减少后可见初始牌刚好已齐，例如2人第一遍输入3张后改为1人，启用简便暗牌时，预览会明确说明新增一张未知底牌；同批事务只登记一次。没有自动确认非BJ。修改发布后，旧当前概率失效；历史前缀仍能重放原人数和原牌局。

针对性测试覆盖7→6后继续录牌并结算、6→7、取消预览、重复加减与牌面纠错、正反方向、空间键暂停、数据库事务失败、计划保存失败、过期预览、同靴同轮和界面重启恢复。验证记录以实际本地及CI日志为准；旧版三靴报告不作为这次修改的实测结果。
