# YOLO11n 首轮成熟框架对照

已完成一个固定版本的成熟框架对照，保留原捕获、分类、时序和人工审核接口。首轮实际结果没有支持替换：31 个新可读事件中，YOLO11n 正确稳定 14 个，本轮冻结基线 17 个；两者可判错误稳定事件均为 3。YOLO 成功事件的条件延迟更短，但漏识更多、计算开销更大，不能据此称整体更快或更准。

只选 Ultralytics 8.3.221 的 YOLO11n，使用官方预训练初始化，未同时试其他 YOLO 版本。单独的 Python 3.12 环境只读引用现有 CUDA/视觉包；安装未更新原环境。`pip check` 通过，GPU 初始合成空白图推理通过，不把这一 smoke 当识牌成绩。

## 完整小图标注与固定训练

原有 20:03/20:21 人审框并不代表整帧目标完整，不能直接把未标注区域当 YOLO 负例。本轮先生成 44 张 320×320 原生上下文小图并全部查看，独立保存助手复核层，原标签不改写。训练候选中 11 张因截断字符或边界完整性不确定而排除；保留 25 张训练小图，其中含 4 张空台小图，共 65 个上角目标。补入 4 个训练漏标框；8 张历史开发验证图补入 3 个框后共 28 个目标。下角、花色图案、桌面文字及计分不作上角目标。

两个训练文件源摘要为 `3831ddee…`、`8d62e197…`，验证文件为 `80cafcdc…`；源及帧分离，但尚未证明两个录像对应独立会话或牌靴。所有新增完整性和框复核均标助手来源、`human_confirmed=false`，不是新增人审牌级，更不是 65 张独立牌。11 张排除项及原始草案保留。本轮小样本尚未覆盖全部反光、叠牌、边缘和移动条件。

固定训练 160 epoch、batch 8、种子 914、AdamW，输入 320，关闭翻转、mosaic、mixup、尺寸缩放和自动混合精度；使用有限颜色变化与 ±15 度旋转。不按测试视频调阈值。训练及框架结束检查约 84.46 秒。只使用固定第 160 epoch 的 `last.pt`；框架最后也执行 `best.pt` 验证，核对两者全部模型状态张量相等，未另选较高分 checkpoint。

框架最后对 8 张开发小图报告定位召回约 0.857、mAP50 约 0.936、mAP50–95 约 0.370。它们是框架检测指标，既不是准确识别 13 种牌级，也不是连续事件或全牌局验收。

这条路线同时改变了检测框架和检测训练数据：冻结基线使用较多部分标注，YOLO 使用较少完整小图。因此它回答这次具体方案能否替代，不能孤立证明某种架构的技术上限。

## 接入及历史静态诊断

本机 `yolo_corner_adapter.py` 继承原有 `TrainedModelAdapter`，验证明确的模型目录、版本、类别、文件摘要及计划；单类别只定位正向上角，牌级仍使用冻结 `ce2232` CNN 与 Otsu。相同 320/160 原生分块、区域归属和全局 NMS 0.3，检测门槛 0.35、最多 96 输出。33 个 tile 分批推理，不缩小整帧。记录 tile/全局容量截断，所有结果仍待人工复核。

实际调用使用私有 CLI 的显式模型选择，核心预览窗口、来源和会话代码与提交 `bd488c49de0bfd122c2162b6a663f595aec3980c` 相同；私有适配器、CLI、截图 worker 及运行驱动分别冻结摘要。集成 smoke 使用训练来源，只验证接口和不写账本，不算外部识牌成绩。

旧 20:21 已参与 YOLO 训练，静态对照明确排除。其余 19 张历史图、163 个旧目标：基线 93 正确/6 错认/48 拒识/14 未匹配，YOLO 87/6/48/22；额外接受输出 29/26，未全部判真伪。旧目标是部分标注，不能当整帧精确率。
