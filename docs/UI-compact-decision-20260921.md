# UI-1～UI-3 简洁决策面板

基线为 PR #14 的 `1cc8c65e15f51ef7e4ab1c3a187b381eee425c50`。此项使用独立分支 `codex/ui-compact-decision-20260921`，是呈现和交互改动；原牌靴、事件、规则、数值公式、精度和计算预算保持原代码。

## 日常入口

软件默认打开720×500小面板，最小660×460。上方固定显示庄家明牌、分析玩家、实际行动手及牌面点数。按原始投注最终合计EV展示前两项，动作字最大，净盈利概率其次，EV为辅助数字。加倍／分牌显示立即追加单位。结果为负时明确“最佳仅代表相对少亏”；当前手牌不表示下一轮有优势。

“展开详情”打开同一结果的完整报告，包括净盈利／不盈不亏／净亏损概率、EV差距、爆牌概率、收益分布、投入、规则、引擎版本和输入摘要。展开、收起、切换工作台不启动新计算、不复制分析服务。

“录牌／纠错”直接展开当前录入位置、点值、暗牌、揭示模式、动作、暂停与撤销；原始精确牌面、花色、事件修正和本轮座位设置仍在“记录／修正／设置”。录入目标与分析对象继续分开。数字键沿用原键盘绑定。推荐失效时保留结果区域的高度，连续录牌按钮不随数值消失而跳动。

“研究工作台”单独进入原完整工作台；历史复算、规则、实验、牌靴组成、事件时间线、导入导出和诊断均保留。返回小面板继续使用同一账本与请求。默认不打开完整工作台、详情窗口或时间线。

## 摘要契约

`analysis/decision_summary.py`只读取已发布结构化结果；不解析展示文本，不调用求解器，不预选两个动作来计算。

- 遍历输入声明的全部合法动作，以EV排序；仅把前两项交给默认视图，完整比较保留在详情。
- 每个动作的净盈利概率为`sum(P(net) for net > 0)`，零收益属于不盈不亏，负收益属于净亏损。分牌／DAS读取已有合计净收益分布，绝不累加两手各自胜率。
- 使用结果现有`numerical_tolerance`判定并列，不改引擎精度。三项及以上并列提示展开；次佳与后续动作并列也明确标注。
- 合法动作缺失、待核对或`partial_comparison`成立时显示“部分比较”，行标签为“已算第1／第2”或“已算中并列”。不标为全局最佳。
- 只有一项合法动作只展示一项。确定补牌`deal`与完成`complete`为流程状态，没有新的玩家操作建议。
- 分布缺失、非有限数值、概率归一或EV不一致时不给数字，不把缺失补成0。
- 历史复算明确显示“历史”，牌面来自原时点；“返回当前手牌”清除历史建议后重新核对当前输入。查看首手但第二手实际行动时，首行突出第二手并注明所查看的手。

`AnalysisPanel`仍是唯一请求所有者。保留原进程隔离、5秒预算、取消、同步失效通知、请求ID和输入摘要核对、独立历史快照。小面板是它的视图；新牌、撤销、纠错、换目标或会话使两个视图的当前数值同步失效。

## 逐项验收

| 要求 | 可核对证据 |
| --- | --- |
| 单手、分牌、DAS同一概率口径；按EV而非净盈利概率排序 | `tests/test_decision_summary.py`：真实单手与原生分牌/DAS完整动作结果，以及低净盈利概率却较高EV的反例、两手一赢一输归零 |
| 并列、次佳并列、部分比较、唯一动作 | 摘要用例与`test_tie_and_single_action_labels_are_not_fabricated`；原生部分比较截图 |
| 默认两项无需滚动；详情和研究分层 | 720×500、660×460几何检查及Computer Use实际截图；启动时工作台和时间线未映射 |
| 展开前后数值、任务相同 | `test_expand_and_workbench_share_one_result_no_extra_request`，同一对象、request_id、snapshot；原生窗口展开前后请求数仍为1 |
| 录牌、撤销、纠错、切手、取消、超时、历史切换 | `tests/test_compact_panel.py`、原`test_analysis_ui`和PR14/K-F5回归；新事件提交即清除两视图，原快照保留 |
| 加倍唯一补牌、两手完成等待庄家 | 单手和DAS自动用例；原生DAS第二手加倍→补T→庄家截图与逐步状态 |
| 不显示旧结果或用0替代缺失 | 有效请求身份保持原发布门禁；取消、超时、缺口、无效分布和跳过一般重绘的失效用例 |
| 数学、规则、精度、存储及框架不变 | 与基线的核心、账本、存储、服务、输入契约、C#目录差异为空；新增模块仅聚合与排序结果 |

本地完整回归505项通过（503项执行成功，2项因缺少原336性能材料跳过，209.342秒）。补充次佳并列与完整联合分布展示后22项专项检查通过（9.723秒）；编译、原数学交接与48项补充场景通过，最大绝对误差2.22e-16。新增一项后完整套件为506项；最终远程结果以该提交对应日志与独立回执为准，不能沿用PR #14旧CI。

原生截图来自2560×1440、约96 DPI目标机。测试引导程序只创建新的自建临时库、录入固定牌例并调用真实计算；随后由Computer Use点击展开、录牌、撤销、重算及分牌加倍流程。不是对真实平台、真人速度或长期体验的验收。首轮截图暴露录入区跳动，原图保留；最终截图验证固定区域后已消除跳动。

## 复现与交付边界

```powershell
python -m blackjack_lab.main --prepare-split
python -m unittest tests.test_decision_summary tests.test_compact_panel -v
python -m unittest discover -s tests -v
python -m compileall -q blackjack_lab tests scripts
python scripts/verify_review_handoff.py
python scripts/preview_compact_panel.py --output .local-evidence/新的唯一目录 --scenario das
```

预览输出目录已存在时拒绝覆盖；场景可选`empty/single/partial/split/das/forced/complete`。预览不会打开默认用户数据库。原工作台截图脚本现在显式打开工作台后再检查原尺寸，保持其验证范围。

按现有仓库更新授权另行提交供审查，不合并main，不发布安装包。没有整合PR #13、实现多人EV、开局优势或新规则。所有本地数据及原验收包继续保留；GitHub只提交源码、测试、复现工具与说明。

设计参考：[Microsoft逐步展开控件](https://learn.microsoft.com/en-us/windows/win32/uxguide/ctrl-progressive-disclosure-controls)（其样式示例是旧版Windows指南，仅采用按需展开原则）；[Python Tk事件模型](https://docs.python.org/zh-cn/3.13/library/tkinter.html)。较重计算继续在现有进程服务中执行。
