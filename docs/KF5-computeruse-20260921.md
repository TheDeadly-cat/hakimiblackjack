## 两轮结果

1. 第一轮顺序 `0 7 1 6 0 0 9 .`：玩家1为T/T、玩家3为7/T、玩家5为A/9，庄家6与暗牌；空座位跳过，分析身份保持玩家5。
2. Space暂停后按2被明确拒绝，账本仍为11条。恢复后故意录入2，玩家1爆牌并转玩家3；Backspace撤销后恢复玩家1的T/T及录入目标。
3. 连续三次实际停牌转庄家；在揭示模式录入9沿用原暗牌事件，再切回新发牌录入2。结算分别为+1、0、+1个自建单位。
4. 第二轮只保留玩家1：8/8对庄家6与暗牌，分牌后首手补9停牌，次手补3后DAS补T形成21。提示、座位与实际hand_id转为庄家，“刚刚记入”仍正确标为玩家1。
5. 庄家揭示9、补2至17，结算首手平、第二手加倍胜，净值0与+2个自建单位。
6. 启动第三轮后关闭程序，重新打开并选择恢复。会话身份、34条完整事件、整个计划对象与关闭前完全相同；焦点是第三轮s1／玩家1第一张。

两轮有效新可见牌15张，原暗牌揭示2次；故意误录1张已撤销。共17张实际离靴，8副牌应剩399张。只有一次预设暂停拦截，无意外业务错误。工具层还出现不支持的 `asterisk` 键名，改用支持的 `Numpad_Multiply`，确认只追加一次加倍事件。

## 发现并修复的提示缺陷

撤销续牌后，牌面和下一目标正确，但“刚刚记入”仍声称被撤销的2已保存。截图与状态 `014-undo-bust` 能复现。续牌没有初始槽位，旧清理逻辑只在撤销初始牌时清空该提示。

本补丁在计划与有效牌事件核对时清除已失效的最近牌面提示。既覆盖当场撤销，也覆盖载入旧计划中遗留的提示；不重写旧事件、不改变牌数或数学计算。界面显示“刚刚记入：—”，状态栏与事件列表保留撤销说明。

针对性验证：`python -m unittest tests.test_deal_entry tests.test_kf5_followthrough tests.test_pr14_reliability -v`，48项通过（29.837秒）。新增旧计划失效提示用例，并扩充爆牌撤销→重启→再爆牌用例。完整远程检查另绑定最终提交，不能沿用5004d79的483项结果。

修复后的原生窗口复验曾在会话恢复对话框被 Computer Use 焦点错误阻断：`foreground window did not report a process id`。刷新窗口、激活并重试后仍失败，未盲目补发输入。修复后的原生截图结论以独立补充回执为准，不把自动回归当作该次原生复验。
