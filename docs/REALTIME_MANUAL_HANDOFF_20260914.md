# 实时来源到人工核对

主程序的实时录像与窗口预览支持「冻结识别帧并核对」。点击后停止该次来源，将已显示候选对应的原始识别帧交给现有人工核对页：原图、选中位置、可横向滚动的裁片，以及新牌／揭示／纠错操作。保存快照不会扣牌，操作和座位必须明确选择后才能确认。

## 使用入口

在项目目录使用已安装视觉依赖的 Python 启动主程序：

```powershell
& '.\.local-evidence\rgb-corner-prototype\venv\Scripts\python.exe' -m blackjack_lab.main
```

1. 主程序打开「识牌核对」，选择本地样式、对应训练模型和录像。需要正式记录时，先在主程序开靴、开轮，再绑定当前轮。
2. 点击「1倍速实时预览」。候选与短时稳定值仍自动显示，无需逐帧确认。
3. 点击「冻结识别帧并核对」，返回静态核对页。该页显示确切原录像帧号和媒体时刻；冻结的是候选对应的识别输入，播放器可能已经显示更新的画面。
4. 点击裁片或选择观察 ID，原图同步标出位置。向右滚动可检查末尾候选。人工选择新牌、揭示或纠正已有事件、座位与牌面，再确认入账。选换候选会刷新牌面提示、清除旧纠错目标；未知归属保持空白。
5. 遮挡或移牌后，如果此候选是已经记录的牌，选择「同一张已记录的牌（仅关联）」，从原发牌记录中明确选择对应牌，再点击「确认关联（不扣牌）」。列表显示序号、当前座位／手牌和牌级，分牌后的两张 A 分别选择各自记录。关联操作不改变模型输出或账本牌面。
6. 以后可点击「打开核对快照」，选择该次保存的 `handoff.json`。先恢复原会话并绑定同一靴／轮；打开后显示保存的原图、裁片、原预测和已保存关联，不重新运行模型。选中裁片会在布局完成后自动滚到可见区域。

窗口输入：选好归一化样式和匹配训练模型后，点击「选择窗口实时预览」，在窗口列表中选中来源，再点击「开始所选窗口预览」。此时才开始 WGC 捕获，按当前样式裁区；没有额外显示器采集器。窗口预览同样可冻结到人工核对，也可停止或重新捕获。缺少捕获依赖时保留原核对页，按 `requirements-capture.txt` 安装；窗口关闭、最小化或更换进程后停止来源，不自动换选其他窗口。

此入口位于主程序的「识牌核对」页。独立的 `scripts/realtime_preview.py`／`Start_Realtime_Preview.cmd` 演示窗口没有绑定人工核对页，不显示冻结核对按钮。WGC 快照保存窗口身份、采集序号和采集时刻；录像帧号与录像相对时间保持空值。

## 数据与生命周期

- 录像生产者将确切解码帧号写入可选 `source_frame_index`；接帧队列序号和 WGC 媒体时钟不能当成原录像帧号。WGC 不填这个字段，旧记录不补造。
- 只接受当前会话保留的识别结果，检查来源摘要、媒体时刻、模型、区域及图像身份。画面选择使用已显示结果，不使用后台刚完成、用户还未看到的结果。
- 深拷贝原始模型输出和该帧像素，不重新推理，不用历史稳定牌级改写本帧候选。源图与裁片在后台保存；等原推理线程结束后再导入核对页。
- 预览的临时 ID 不写入账本，核对沿用原人工 `FrameTracker` 与 `VisionReviewSession`。原确认记录保留；相同确认请求保持幂等，两张同牌面候选仍分别处理。既有稀疏帧关联仍可能不准确，不能把此桥接称为完整物理身份验收。
- 预览启动后如果改了录像、模型、区域或轮次，旧入口拒绝导入；保存期间原核对结果或账本版本改变，也不覆盖当前工作。
- 每次显式冻结保存一个独立证据目录，已有目录不覆盖。源图、裁片、原模型输出、人工核对 ID、来源时钟、请求时的轮次及摘要可追查。没有逐帧落盘，也没有新采集器。
- 窗口销毁时取消它持有的定时回调，并停止预览；核对页关闭时取消待导入回调并释放本地录像。

证据保存在 SQLite 文件旁的 `.vision/<视频摘要前16位>/realtime/<快照ID>/`。`handoff.json` 保留原始识别与转交身份，人工确认凭据仍使用现有证据目录下的 `confirmations/`。快照文件存在不表示已经人审或已经入账。

## 显式同牌关联与快照恢复增量

人工关联只引用本轮仍存在的已确认发牌事件；撤销后的牌和旧轮记录不能作为目标。目标列表使用重放后的当前位置，所以分牌会显示不同手牌。同一帧两个候选不能共用一个目标，关联过的候选也不能直接再当新牌扣除。关联错误可以「拒绝候选 / 撤回关联」后重选；原账本记录保留，已经真实入账的观察仍须走账本纠错或撤销。

关联凭据独立保存在 `.vision/<来源摘要前16位>/identity-links/`，包括原观察、目标事件、绑定上下文、前一动作和原因，不新增账本事件类型或数据库结构。替换／撤回保留旧动作文件；恢复时凭据缺失或摘要不一致会报错。原稀疏帧跟踪器可能误用旧 ID，因此相同 ID 的像素、位置或源帧改变后，旧关联只保留为历史保护，必须重新核对当前图像，不能自动继承“已确认”。

新快照同时保存候选 JSON、源 PNG 和原始 RGB 摘要；打开前检查文件范围、身份、坐标以及当前会话／靴／轮，失败时保留原核对页。旧快照缺少候选 JSON 摘要的，不能通过新增恢复入口导入，仍可查看原图或重新冻结；没有改写旧证据。打开快照会清除活动录像／模型配置，避免把存档当成新的实时识别。
