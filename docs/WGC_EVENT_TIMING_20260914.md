# WGC 逐事件时钟与原图绘制区间

实际 WGC 已从捕获连通性检查推进到逐事件评分：保留原始 WinRT 时间，通过像素签名和独立原播放器记录关联视频时间，再对实际绘制结果评分。最后两轮原生源窗口完整播放约 92 秒，仍未达到首候选 P95≤0.5 秒、正确稳定 P95≤1 秒的目标；RGB 不替代旧方案。

## 评分入口与时钟边界

新增 `scripts/evaluate_wgc_events.py`。输入为原运行、原收据、该轮驱动脚本快照和冻结事件参考；入口检查运行与脚本 SHA256、窗口所有者、完整播放／释放、模型摘要、原生捕获尺寸和非空完整像素抽查。样本签名不是完整图像摘要，因此另外保留逐次全像素 SHA256 抽查，不能声称每一帧都做过全像素校验。

结果窗口保持实际缩放约 0.775，作为可读时刻参考的自有原图播放器为原生 1850×520。评分没有把缩小的结果窗口篡改成 1.0，也没有把 WinRT 绝对媒体时间直接当视频秒数。派生事件保留原 WGC 帧号、WinRT 时间和关联签名。原始运行／参考都不改写。

两项计时修正来自真实运行：

- 原来只有取证探针和推理输入记录签名，部分仅显示过的帧没有对应记录。现在 `source_displays` 也保存已有帧签名、尺寸及裁区，无额外图像副本；旧记录中的缺口继续保留。
- 原播放器的 after-idle 绘制回执有时明显晚于捕获回执，第二组旧方案最大相差约 292 ms。不能用这个偏晚的回执直接作为延迟起点。最后两轮额外记录调用原图 canvas 更新之前的时间：首次可读下界取前侧源帧的更新请求时间，上界取后侧源帧的绘制回执。区间包含原图标注范围和这两个回调端点，仍不声称测到了显示器扫描时刻。

同一原图可能被稍后再次提交。评分只按已记录的先后关系排除捕获到达之后才发出的绘制请求；若此前仍有多个可能来源，就保留未判，不能任意取最近一个。一次旧方案评分起初误将重复签名直接判为全像素校验失败；该次捕获的完整像素实际一致，第二次同签名的绘制请求在捕获之后。失败信息单独保留，并增加了手算用例验证这一因果关系，没有修改录像、模型、原运行或检测阈值。

源视频、1850×520 ROI、固定 36 个事件参考和旧／RGB 权重均与 [原八轮事件对照](REALTIME_EVENT_MATRIX_20260913.md)相同。36 个事件分为 5 个开场已有目标和 31 个新可读目标；下表仅列后者，所有目标保留在分母中。位置参考仍有未判区域，结果为可判锚点上的已验证计数，不能解释成完整全帧召回。

旧方案的结果分组为：12 个曾正确稳定、1 个仅错误稳定、11 个只有未知牌级候选、7 个未匹配；RGB 为 9 个曾正确稳定、2 个接受但未正确稳定、2 个仅未知候选、18 个未匹配。旧方案 1 个事件曾出现错误候选和错误稳定；RGB 分别为 2 和 1，后者有一次稳定值改正，原错误仍保留。两轮在可判锚点未找到跨参考目标的 ID 合并，但有多个 ID 的参考目标分别为 9／8 个；不是完整物理身份通过。

RGB 未对应的 WGC 帧 878，推理记录为第 589 行，0 个观察；相关第 588 行显示更新也没有当前轨迹。它的签名不在原图绘制日志中，不能猜测来源或补写对应关系。其余输入均可对应；该缺口没有隐藏一个已接受输出，但仍保留未判标记。布局继续为 `unassigned`，座位错误数不是 0，而是未评分；正式记账仍未执行。

最终旧／RGB 运行分别记录 1／0 个 Tk 鼠标事件，键盘事件均为 0；鼠标事件不解释成改牌次数。来源、播放器和推理线程均正常结束，运行没有报错。取帧→显示分位数只取实际有显示回执的 597／663 行，其余处理行未硬填显示时间。
