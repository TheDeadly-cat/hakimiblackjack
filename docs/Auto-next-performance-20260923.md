# 自动下一局、十点不检查与录牌性能

基线：PR #22，`11ef4e69ebb76144356f33f4e98a6eede3066f88`。本次独立分支 `codex/auto-next-flow-20260923`，保留草稿审查，不合并 main。

## 使用行为

- 默认 S17：庄家 16 点继续补牌，硬/软 17 点及以上停止，爆牌也结束。玩家动作完成、全部牌面已知且没有观察缺口时，最后一张庄家牌触发结算并进入下一局。只在成功录牌时触发，刷新、恢复、撤销不自动跳局。
- 最后录牌、结算、新开轮在同一数据库事务内保存。Backspace 一次撤回这三个事件，并恢复录入位置；如果下一局已经录牌，先撤回新牌，再撤回跳转。原事件仍保留。
- 新牌盒默认只在 A 明牌时要求真实非 BJ 检查，十点明牌直接继续玩家动作。没有伪造 `PEEK_NEGATIVE`。未知底牌仍可能是 A，动作和开局 EV 都保留庄家 BJ 风险，追加注按现有规则全部损失。未排除庄家 BJ 时晚投降不可用。
- 现有牌盒和历史模板保留原规则；使用“一键常用设置”后新建牌盒启用新规则，不改写旧记录。
- 每项动作都显示正 EV、负 EV、零 EV或不适用/未支持；当前目标的全部动作集中显示，多人表保留每人的前两项。切换分析玩家可查看该人的全部动作。
- 发牌前保留顶部下轮投注 EV；开始发牌后清除开局值，所有初始槽位录齐前不准备或启动手牌 EV，录齐后自动计算。多人条件仍是“其他玩家之后不再补牌”。

## 性能

定位到同一输入被逐座位重复验证，以及一张牌的界面回调反复重放全部记录。现在同一可见事件前缀只验证一次，多个座位共用已验证上下文；不可变结果按完整内容摘要缓存。新增、撤销、纠错、换会话及内容改变都会失效。只读重放在单个界面回调内复用，写入验证独立执行，缓存不跨回调保留。合并状态通知的重复绘制，初始发牌不建立计算任务。

相同临时数据、7 人、此前完整记录 6 轮，再连续录 14 张初始牌，最终 167 个事件；关闭计算进程并使用相同绘制方式，排除计算任务负载，仅比较录牌回调及界面提交延迟。Windows / Python 3.14，未开启性能分析器的结果：

| 指标 | 基线 | 本次 |
|---|---:|---:|
| 单张中位数 | 154.02 ms | 62.19 ms |
| 单张最大值 | 173.07 ms | 67.27 ms |

本场景中位数下降约 60%。这是一次可复现的本机录牌测量，不是所有电脑、任意长度会话或整靴真人试用的保证。原始测量位于 `docs/acceptance/auto-next-20260923/`。

```powershell
python scripts/benchmark_recording.py result.json --no-profile
python scripts/benchmark_recording.py baseline.json --source <基线运行目录> --no-profile
```

## 验证与边界

新增回归覆盖自动结算、单次通知、事务失败、16/软17/H17/爆牌、恢复后组合撤回、七人反向顺序、按住数字键不跨局多发牌、计划保存失败仍暂停、初始发牌零计算及缓存失效。十点不检查的单手和两手 DAS 与独立分数枚举核对；开局模拟使用一张 A 加 31 张十点牌的独立位置枚举核对追加注损失。

开局估算引擎/策略更新为 v2，原 v1 固定运行副本保留。开局仍是有限不放回、固定策略的蒙特卡洛估计，显示 95% 抽样误差区间；不是有限牌盒最优策略。牌数不足以完成该策略时拒绝给出结果。

本机完整回归首次 644 项仅一处旧“17点后等待手动结算”的断言失败，已更新为新行为；相关 48 项和数学 7 项复测通过。最终提交的完整 Windows CI 和原生窗口验收以该草稿 PR 回执为准。未重跑三整靴真人试用，也未合并历史未合并分支链。
