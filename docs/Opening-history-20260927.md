# 开局估算独立留痕

点击顶部“下轮EV估算·固定策略”打开详情，再点“开局历史 / 原时点复算”。完成的开局结果自动保存，不会在重启后冒充当前牌况。原结果只读；按原时点复算创建新记录并保留来源ID。顶部仍只显示当前有效输入的结果，第一张牌入账后立即失效。

存储位置为数据库路径加 `.opening/`，例如 `data/blackjack_lab.db.opening/`，格式为 `hakimi-opening-snapshot-v1`。不修改SQLite结构，不写入发牌事件，不伪装为手牌分析快照。备份时应同时保留数据库、`.analysis/`、`.opening/` 和 `.deal_plans/`。

每条记录包含：

- 完整输入、锁定桌规、参与人数及本人位置、输入和规则摘要；
- 当时完整事件前缀及摘要、序号、会话/牌靴/轮次身份；
- 固定策略、算法版本、Python与C#源码摘要、原生程序摘要；
- 种子、200万完整样本的17格收益直方图、EV/优势率/方差/95%区间；
- 请求、保存时间、计算耗时、状态以及可选的原复算来源。

取消、输入失效、超时、失败、不支持单独分类，不能携带可用EV或部分样本。完成记录须从完整直方图重新核算数值，并核对输入能从保存的事件前缀重建。

文件采用原子新建，原文件不覆盖。保存失败显示“已计算、未保存”，待保存内容保留在当前进程，可显式重试；即使之后录牌，重试仍保存原输入前缀，不把结果绑定到新牌面。保存错误不回滚卡牌事务。未成功保存的内存结果在退出前应重试保存。

内嵌前缀让原结果可读，但不能代替原数据库验证。历史复算通过只读连接核对数据库中的同一会话/序号/内容；数据库缺失、被替换或前缀不同会禁止复算，不自动创建空数据库，也不把它标为已验证。旧源码结果可只读展示；当前发布仍要求当前算法来源一致。

损坏记录按文件报告并保留。没有删除、覆盖或静默修复旧记录的入口。存储摘要用于检出不一致，不代表外部签名或真实牌桌的真实性认证。

历史列表在后台完整核验，窗口先打开并显示读取状态，期间可继续录牌；读取完成前不能发起历史复算。关闭窗口会取消读取，未完成的列表不会当作完整结果发布。此改动避免历史记录较多时阻塞主界面，不减少校验项目，也不改变原文件。

定向验证：`python -m unittest tests.test_opening_history tests.test_opening_ui tests.test_opening_ev tests.test_auto_next tests.test_new_shoe_anytime -v`。包括保存失败后继续录牌并重试、不可变原文件、重启只读、复算另存、缺失/不同数据库、损坏文件、状态隔离、当前失效、取消与超时，以及原卡牌事务/撤回回归。
