# Hakimi Blackjack Lab — V0.2a

**输入当前手牌，在庄家底牌未揭示时计算概率与单手动作 EV，并保存当时判断供复盘。**

本版保留 Python、Tkinter 和 SQLite，交付必要可靠性修复与首个受限手动分析闭环。当前软件版本 `0.2.0a1`；V0.2a 不是完整 V0.2，不包含分牌 EV、多玩家 EV、识别或捕获。

## 开始使用

Windows / Python 3.10+（含 Tkinter）。运行核心功能只用标准库，无需 API Key。目标验收环境为 Windows 11 / Python 3.14.6。

双击 **启动界面.bat**，或在项目根目录运行：

```powershell
python -m blackjack_lab.main
```

第一次可以导入 `fixtures/v02a/demo-7decks-16-vs-T.json`，然后点右侧“计算当前手牌”。该文件是明确标记的自建演示数据，底牌仍未知；它不是平台记录或投注建议。

自己录入时：

1. 选 6／7／8 副，点“载入研究模板（新靴用）”，再点“新建牌靴”。研究模板不是任何平台的默认桌规；实际规则不同应保留真实记录，并接受未支持提示。
2. 勾选本轮一个参与玩家，点“新开一轮”。仍可记录最多 7 位玩家，但本版分析只支持单参与玩家、单手、未分牌。
3. 录入两张玩家牌、庄家明牌和一张“暗牌”。庄家明牌为 A 或十点时，必须有实际的非 BJ 检查信息，再点“庄家检查底牌：确认非 BJ”。未知结果不要自行勾选。
4. 点右侧“计算当前手牌”。可选“自动”，在合格输入变化后自动发起新请求。窗口可以继续录入；新牌、撤销、纠错、换目标或换会话会让旧结果过期。
5. 面板显示停牌、补牌、加倍及合法晚投降的 EV、补一张爆牌概率、下一次目标抽牌分布和庄家终局分布。下方可滚动查看全部概率、规则、策略、版本、输入摘要与耗时。
6. 结果自动保存为独立快照。点“历史分析 / 复算”可读取原结果，或按原事件前缀使用当前引擎重新计算；重算生成新快照，不覆盖原判断。

## 分析范围与含义

唯一已验收的首发规则族：有限不放回；6／7／8 副；完整新靴；明确初始烧牌数为零；S17；Blackjack 净赔付 3:2；美式底牌；A／十点明牌在玩家决策前明确检查非 BJ；初始两张可加倍；无投降或晚投降。

- 正常未知底牌作为隐藏变量计算。非 BJ 检查既影响底牌候选，也影响下一张玩家牌的条件概率；不会把账面剩余数直接除以物理待发数。
- 补牌 EV 包含之后按新见牌在补／停之间继续决策，不是强制补一张后停牌，也没有偷看底牌再选策略。
- EV 是**相对原始一单位初始注的最终净收益**。加倍按 -2／0／+2 结算，返还本金不算盈利。每个支持动作还保存同口径收益分布。
- 若分牌合法但分牌 EV 未实现，显著显示“部分动作比较”，不提供唯一推荐。只有当前全部合法动作完成计算且超过数值区分阈值，才标示声明模型下 EV 最高的动作。
- 全部动作 EV 为负时会明确提示。较高可能只意味着少亏；当前手牌 EV **不等于下一轮开局优势**，本版不输出注额建议。
- 未知起靴、未知初始烧牌数、漏牌、待确认牌或未支持规则会阻止相应精确分析。旧规则中没有初始烧牌数字，不会自动当零。
- H17、6:5、已知非零烧牌、其他底牌规则、已分牌和多玩家分析尚未验收；保留记录能力，不套用研究模板代算。

数学定义与独立参考见 [数学契约](docs/V0.2a数学契约.md)，要求对应关系见 [验收矩阵](docs/V0.2a验收矩阵.md)，完整路线见 [调整版r1](docs/planning/开发大纲调整版-r1-20260910.md)。

## 记录、保存与恢复

- 默认数据库 `data/blackjack_lab.db`；分析旁路目录为 `data/blackjack_lab.db.analysis/`。也可使用 `python -m blackjack_lab.main --db "D:\Records\lab.db"` 指定其他文件。
- 原事件继续使用 SQLite schema 2。分析写失败会单独提示，可重试；不会回滚已经提交的牌面事件。
- “已提交但界面刷新失败”与“事件未提交”分开提示。前者请刷新或重启，不要重复录牌。
- 导出 JSON/CSV 使用原子替换，写到一半失败时保留原文件；拒绝导出到活动数据库、数据库别名或 SQLite 文件。
- CSV 展示列中可能触发公式的文本会转义，`event_json` 保留原始审计内容。旧摘要 CSV 只读，不能假装完整导入。
- 旧非法记录可在“旧会话诊断”中只读检查和原样导出，不自动改正或作为正式分析输入。
- 稳定备份请在关闭程序后同时复制数据库和同名 `.analysis` 目录。“备份数据库”按钮只备份 SQLite，不包含旁路分析目录。
- 键盘：0=10，A/J/Q/K 录牌，T=十点未细分，X=庄家暗牌，G/B/V=停牌/加倍/分牌，Ctrl+Z 撤销。输入框里不会触发录牌快捷键。

## 验证和开发

```powershell
python -m unittest discover -s tests -v
python -m blackjack_lab.main --check
python -m compileall -q blackjack_lab tests scripts
```

完整验收（额外截图步骤使用可选开发依赖 Pillow）：

```powershell
python -m pip install -r requirements-qa.txt
python scripts/verify_release.py
```

每次在 `.local-evidence/acceptance-v02a-时间-随机标识/` 创建独立目录，不覆盖原报告。包含真实命令、退出码、源文件哈希、独立小牌靴有理数验证、禁止 socket 网络连接的独立进程工作流、固定种子模拟、目标机延迟/内存和真实窗口截图。`--output` 可指定新的目录，已存在目录会被拒绝。

性能场景、统计方法与预定阈值写在 `scripts/analysis_checks.py`。模拟以独立轮为采样单位；两个动作复用同一组轮，不把它们相加成独立样本。精确有理数参考使用绝对误差 1e-10；模拟另报标准误与95%区间，不要求随机均值逐位相等。

原 V0.1、V0.1.1 文档与失败输出保留为历史证据。当前能力以本 README 和 V0.2a 验收矩阵为准。许可证边界见 `NOTICE.md`。没有平台适配、自动下注、云端识牌或实时捕获。
