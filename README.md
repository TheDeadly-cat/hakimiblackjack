# Hakimi Blackjack Lab — 逐玩家条件分析（含显式两手 DAS 模板）

**分牌前比较动作，分牌后逐张更新当前操作、原始投注的合计 EV 和净收益分布，并保存历史复盘。**

产品显示版本 `0.2.0b1`。规则模板、求解引擎是另一套身份：无 DAS 为 `v0.2b1-finite-two-hand-1`；两手 DAS 生产引擎为 `v0.2b2-finite-two-hand-das-2`。保留 Python、Tkinter 和 SQLite。多人采用逐玩家条件比较：假设其他玩家之后不再补牌，并非整桌后续策略模拟。没有再分、识别、捕获或真实平台接入。两手 DAS **只在显式 V0.2b2 模板**下计算，不会把旧无 DAS 快照改写成新引擎。数学与工作流验证、目标机性能、CI 和交付证据分别报告；318 项 unittest、旧 b1 318 冷请求、DAS 336 矩阵不能互相换签。不把测试通过解释为获利保证。Windows DAS 336 门禁与干净运行副本的做法见 [V0.2b2 验收与交付](docs/V0.2b2-验收与交付.md)。


## 开始使用

默认打开**简洁决策面板**：当前局面、按EV排序的最佳／次佳、各自的净盈利概率，以及结果是否仍有效。分牌后概率指本次原始投注的两手合计净收益大于0。并列、部分比较、等待补牌、结果过期会明确显示。

**日常流程精简**：阶段主操作区显示当前应做什么。完整可结算时点“确认完整并下一轮”，一次保存完成收尾和同靴开轮，上轮摘要可随时展开；仍可只结算。最近可见牌旁点“改牌”可就地纠错，撤销按钮注明具体对象。牌面区位置稳定，简洁态／设置态／工作台各自记住窗口尺寸。详见 [FLOW-1](docs/FLOW-1-round-transition.md)、[FLOW-2](docs/FLOW-2-recent-correction.md)、[FLOW-3](docs/FLOW-3-stable-layout.md)。

新建牌靴默认 **8 副牌**，仍可选择6／7副。顶部注明“当前发牌给”哪个座位，并同步显示庄家全部已录牌及点数；底牌未揭示时标为暗牌，不推测点数。结算后明确显示“本轮已结算”，不再提示下一张给庄家。

**常用设置默认就绪**：8副、S17、同值分牌、late晚投降、初始两张可加倍及非A分后加倍，简便暗牌默认开启。首次打开可直接点“新建牌盒”→“开始本轮”。“录牌设置”中有“一键常用设置”，可同时恢复整套选项。已有牌盒和记录继续使用保存时的规则；未知旧桌规不会被预设覆盖。详见[默认与一键常用设置](docs/Common-settings-20260923.md)。

**随时换靴**：主界面顶部的“新建牌靴”始终可用。确认后，未完成的旧轮以未结算方式结束，旧记录保留，再按当前设置建立全新牌靴；发牌中、有未知底牌、暂停或刚自动开下一局也可使用。Backspace一次撤回整次换靴。见[换靴说明](docs/New-shoe-anytime-20260923.md)。

**简便暗牌与自动下一局**：录完初始明牌自动登记一张未知的庄家底牌；轮到庄家直接输入底牌点数，再输入补牌。新牌盒默认只在 A 明牌时要求实际非BJ检查，十点明牌直接继续；未排除BJ时不可晚投降。S17下16点继续补牌，17点及以上或爆牌且记录完整时自动结算进入下一局。Backspace一次撤回最后录牌及自动跳转，原记录保留。旧牌盒保留原检查规则。见[最新流程与性能说明](docs/Auto-next-performance-20260923.md)。

**顶部下轮投注EV估算**：发牌前按当前剩余组成、人数及本人座位自动模拟每1单位底注的预期净收益，并显示优势率和95%抽样误差。其他玩家使用同一固定策略；只有区间完全高于0才标“正EV估算”，跨0为“正负待定”。录新牌后立即清除旧值，本轮未结束或牌况不完整时等待。点击标题查看本次假设与组成。该值与当前手牌动作EV分开，方法及支持范围见[开局EV说明](docs/Opening-EV-20260923.md)。

右上角 **− 玩家 / + 玩家** 调整下一轮参与人数（1～7人），旁边显示人数；添加最低空座、移除最高且非本人座位，本轮账本不变。需要非连续座位时，仍可在工作台逐个勾选。**自动计算默认开启**：录齐信息后计算，新牌/撤销/纠错后自动更新。多人表分别列出每位玩家按EV排序的两个已算动作、各自净盈利概率及第一项EV；点选玩家，再“展开详情”查看完整动作。待补牌、缺口、已结束等不适用状态明确显示，不填造概率。

多人计算口径已选定为 **“各玩家按当前牌况分别比较，假设其他玩家之后不再补牌”**。所有已知牌都扣入共享剩余牌数，假设及真实参与座位写入独立输入摘要和历史快照；其他玩家有已选择但尚未录入的必补牌时等待补齐。每录一张实际牌，所有人的旧数值立即失效再重算。见[自动与逐玩家条件比较](docs/UI-auto-seats-20260921.md)。

录牌区域快捷键：**Tab／Enter 下一位、Shift+Tab／Shift+Enter 上一位**，按本轮已选参与顺序经过玩家和庄家，末尾循环，空座跳过；默认顺序为玩家1→7→庄家，反向发牌设置仍受尊重。**Ctrl+1～7**直接切到相应玩家，**Ctrl+0**切庄家。切换只移动录牌位置，不会发牌、停牌或更改分析对象；初始发牌时跳过未录位置仍会暂停自动轮转，需在工作台核对对齐。输入框内保留普通键盘行为。

牌面键默认常驻，可收起以便键盘录入；点“录牌设置”展开低频选项，点“展开详情”查看同一计算结果的完整报告；规则、历史、实验与导入导出由“研究工作台”进入。首次使用可直接在小面板新建牌盒，并用右上角加减按钮选择人数。三个层级共用现有本地计算与账本。实现及验收范围见[简洁面板说明](docs/UI-compact-decision-20260921.md)。

Windows 64 位 / Python 3.10+（含 Tkinter）。Python 主程序使用标准库；分牌数值程序另使用系统 .NET Framework 4 编译器和运行时，无新增 pip 运行依赖、API Key、网络服务或下载步骤。目标验收环境为 Windows 11 / Python 3.14.6；分牌加速器当前仅交付 Windows。

双击 **启动界面.bat**，或在项目根目录运行：

```powershell
python -m blackjack_lab.main
```

第一次可以导入 `fixtures/v02b1/split-eight-before.json`，然后点右侧“计算当前手牌”。还可导入 `split-eight-first-bust.json` 查看首手爆牌后继续第二手，或 `split-aces-ordinary-21.json` 查看分A的普通21结算期望。DAS 合成示例见 `fixtures/v02b2/`。这些都是标记为自建模拟器的数据，底牌仍未知；不是平台记录或投注建议。原单手示例仍在 `fixtures/v02a/`。

自己录入时：

1. 选 6／7／8 副，在“研究模板（新靴用）”选择 **V0.2b1 两手顺序分牌模板**，或 **V0.2b2 两手顺序分牌DAS模板**，再新建牌靴。旧模板仍保留原四手录牌规则，不会自动升级为两手或 DAS。研究模板不代表平台桌规。
2. 用顶部增减按钮或工作台勾选下一轮1–7位玩家，选择本人座位，点“新开一轮”。多人保留全部实际参与者，按上述条件假设分别计算。 第一遍发牌发现人数开错时，顶部显示“本轮 N 人”，可直接加减；已录牌归属受影响时先显示确认预览。详见 [第一遍人数调整](docs/First-pass-player-adjustment-20260923.md)。
3. 跟随队列录入所有玩家第一张、庄家明牌、所有玩家第二张；默认自动登记未知底牌，关闭简便模式时再按 `.` 手动登记。默认只在 A 明牌时按真实检查结果确认非BJ；旧 A/十点检查模板仍按原规则执行，未知结果不要自行勾选。
4. 默认自动计算。初始牌未录齐时暂停手牌EV；录齐后自动比较，每项动作标明正EV、负EV、零EV或不可用。窗口可以继续录入；新牌、撤销、纠错、换目标或换会话会立即清除旧结果。
5. 分牌前显示全部合法动作；分牌后选择“按顺序行动手”，先补齐并完成第一手，再给第二手第二张。21 或爆牌后自动切到下一手。DAS 模板下，非 A 分手两张可加倍，只补一张后该手闭合，再继续另一手。面板区分选中手和当前行动手；DAS 分开写当前已投入、立刻追加、此后可能再追加，不把分牌后总投入写成固定 2。不同实际顺序的记录保留，但会阻断该模型的精确分析。
6. 结果自动保存为独立快照。点“历史分析 / 复算”可读取原结果（只读，保留当时引擎身份），或按原事件前缀用**当前生产引擎**另建输入复算；重算生成新快照，不覆盖原判断。旧 b1 快照仍走无 DAS 引擎。T7 的 `das-1` 快照仍可展示，不能用旧引擎重算。

## 分析范围与含义

共同规则前提：有限不放回；6／7／8 副；完整新靴；明确初始零烧牌；S17；天然 BJ 3:2；美式底牌；A／十点明牌在玩家决策前明确非 BJ 检查；初始两张可加倍；无投降或晚投降。V0.2b1 模板增加同原始牌面、最多两手、无再分/无DAS/分A一张/分后无投降及首手完成后才发第二手第二张。V0.2b2 模板相同，但非 A 分手允许一次加倍。

两手共享剩余牌、未知底牌和庄家结算。当前手策略最大化合计净收益，不能提前知道第二手未来牌，也不能用独立卷积替代联合分布。无 DAS 时：分牌前已投入1，分牌另加1，分后总投入2；两手全赢+2、全输-2、一赢一输0。DAS 时每手还可再加1，合计净收益最大 ±4。首手爆牌已经计入已下注额，不能再次扣本金；分A的A+十点是普通21，且禁止 DAS。

初次分牌请求会在本地编译对应源码，编译时间也计入请求预算。可事先运行 `python -m blackjack_lab.main --prepare-split`。派生产物位于 `blackjack_lab/.local-native/<源码摘要>/`，使用前校验产物摘要；缺失编译器或编译失败会明确报告，仍可继续录牌。源码和编译器路径/参数随构建回执保留，不承诺不同机器产物逐字节相同。依赖预检（不安装软件、不改执行策略、不提权）：`python scripts/check_environment.py` 或 `python -m blackjack_lab.main --check-environment`。

- 正常未知底牌作为隐藏变量计算。非 BJ 检查既影响底牌候选，也影响下一张玩家牌的条件概率；不会把账面剩余数直接除以物理待发数。
- 补牌 EV 包含之后按新见牌在补／停之间继续决策，不是强制补一张后停牌，也没有偷看底牌再选策略。
- EV 是**相对原始一单位初始注的最终净收益**。加倍按 -2／0／+2 结算，返还本金不算盈利。每个支持动作还保存同口径收益分布。
- 旧四手模板仍仅作原单手分析，合法分牌缺少 EV 时显示部分比较，不静默截断为两手。全部适用动作完成且超过数值区分阈值时才标示模型下 EV 最高；强制发牌或等待庄家属于确定流程。
- 全部动作 EV 为负时会明确提示。较高可能只意味着少亏；当前手牌 EV **不等于下一轮开局优势**，本版不输出注额建议。
- 未知起靴、未知初始烧牌数、漏牌、待确认牌或未支持规则会阻止相应精确分析。旧规则中没有初始烧牌数字，不会自动当零。
- H17、6:5、非零未知烧牌、其他底牌规则、其他分牌顺序、再分和多玩家分析仍不支持；未声明的旧四手 DAS 组合也不是本契约。保留真实记录，不套用研究模板代算。

两手规则、不可变输入、独立参考和预定性能门槛见 [V0.2b1 数学与性能契约](docs/V0.2b1数学与性能契约.md) 与 [V0.2b2 DAS 契约](docs/V0.2b2-DAS契约.md)。DAS 验收命令见 [V0.2b2 验收与交付](docs/V0.2b2-验收与交付.md)。原单手定义仍见 [V0.2a 数学契约](docs/V0.2a数学契约.md)，完整路线见 [调整版r1](docs/planning/开发大纲调整版-r1-20260910.md)。

庄家新靴默认S17（含软17）：牌面完整且到停牌点后显示“已自动停牌”，停止继续录庄家牌。玩家超过21点会显示“已爆牌”，录入位置自动转到下一位；分牌先转本人的下一手。撤销或改牌会重新判断。详见 [自动停牌与爆牌切换](docs/Automatic-terminal-flow-20260923.md)。

## 记录、保存与恢复

- 默认数据库 `data/blackjack_lab.db`；分析旁路目录为 `data/blackjack_lab.db.analysis/`。也可使用 `python -m blackjack_lab.main --db "D:\Records\lab.db"` 指定其他文件。
- 原事件继续使用 SQLite schema 2。分析写失败会单独提示，可重试；不会回滚已经提交的牌面事件。
- 旧单手快照仍可读，两手输入/结果使用独立格式，复算另存。坏 JSON 按文件隔离并显示文件名与原因，不删除坏文件；最小旧存储信封只显示元数据，不补造 EV。
- “已提交但界面刷新失败”与“事件未提交”分开提示。前者请刷新或重启，不要重复录牌。
- 新记录成功提交时立即撤下旧当前分析，不依赖界面重绘。历史复算明确标注原时点，可以独立完成。
- “结束本轮（未结算）”分别填写原因与观察完整性，默认未知。已知漏录／未知会持续阻止同靴后续精确分析；明确完整但仅暂不结算的轮次可以保留资格。正常“结束本轮并结算”代表确认本轮牌面记录完成。
- 旧结束事件缺少观察完整性字段时保留原文，按未知处理；可在核实后对结束事件追加观察状态纠错。结构性缺牌不能靠声明完整消除。详见 [增量契约](docs/V0.2a观察与生命周期契约.md)。
- 取消计算与关闭“自动”均会清除排队回调；取消后同一输入不会因刷新自行重启，新的输入或显式操作才会重新计算。
- 导出 JSON/CSV 使用原子替换，写到一半失败时保留原文件；拒绝导出到活动数据库、数据库别名或 SQLite 文件。
- CSV 展示列中可能触发公式的文本会转义，`event_json` 保留原始审计内容。旧摘要 CSV 只读，不能假装完整导入。
- 旧非法记录可在“旧会话诊断”中只读检查和原样导出，不自动改正或作为正式分析输入。
- 稳定备份请在关闭程序后同时复制数据库和同名 `.analysis`、`.deal_plans` 目录。“备份数据库”按钮只备份 SQLite，不包含旁路分析与发牌计划目录。
- 数字键单键录牌：`0=T`（10/J/Q/K共同十点桶）、`1=A`、`2–9`；`.` 只确认庄家暗牌存在，不写非BJ检查。长按一次只记一张，释放后再次按同键是另一张。
- 初始顺序固定为“参与玩家第一张→庄家明牌→参与玩家第二张→庄家暗牌”。空座跳过、编号不变；1→7/7→1方向同时用于续牌顺序。
- `Space` 暂停/恢复录入，暂停后数字、暗牌和牌面按钮均不写账，恢复保持原阶段。`Enter`/`Tab`、`Shift+Tab` 只按座位与具体手牌导航；`+`补牌动作、`-`停牌、`*`加倍、`/`分牌、`Backspace`/`Ctrl+Z`撤销。输入框和配置对话框保留普通键盘行为。
- 中部牌桌上方显示完整录入进度、最近保存与下一目标；最后玩家爆牌、最后分手21或DAS唯一牌结束后，录入目标自动转庄家，揭示原暗牌仍不重复扣牌。
- 分牌后导航顺序为玩家1第1手→第2手→下一玩家。录入焦点与分析对象独立；导航不会写停牌事件，也不会允许提前给未轮到的分手发牌。
- 录入计划旁路文件使用 v2，绑定会话、牌靴、轮次及完整事件前缀。SQLite仍为schema 2。已入账而计划写失败时，明确显示已保存并暂停，不能重录。
- 旧版、缺失、坏计划或前缀不一致均保留健康账本并暂停；核对事件后用“核对后人工继续”按显式目标录牌，下一轮重建自动队列。原坏计划在显式继续保存前另存为 `.preserved-*.json`，恢复读取本身不改它。
- 新建表单的常用设置采用同点值DAS模板；旧same_rank模板保持原配对限制，其他桌规可在工作台调整。底层默认接口保留`SINGLE_PLAYER_ONLY`门禁；界面显式请求带`per-seat-others-no-draw-v1`身份的条件比较，不冒充完整多人策略EV。
