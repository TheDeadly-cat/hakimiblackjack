# Hakimi Blackjack Lab

当前版本 **V0.1.1：手动记录闭环修复版**。Python 标准库实现，Windows 中文本地窗口；无需 API Key，不启动网络服务。

本次先复核原 V0.1，再修复记录、结算和恢复缺陷，补齐历史纠错、导入、会话切换和数据库备份。详见 [V0.1.1复核报告](docs/V0.1.1复核报告.md)。原版报告和原测试输出保留为历史记录。

## 启动

安装含 Tkinter 的 Python 3.10+ 后，双击 **启动界面.bat**。本次实际验证环境是 Windows / Python 3.14.6；其他版本未逐一验收。

也可在项目目录运行：

```powershell
python -m blackjack_lab.main
python -m blackjack_lab.main --check
```

默认数据为 `data/blackjack_lab.db`。指定其他数据库可运行：

```powershell
python -m blackjack_lab.main --db "D:\My Records\blackjack.db"
```

首次打开旧版数据库会自动生成同目录 `.pre-v2-随机标识.bak` 备份，再迁移到支持多会话的结构。原版曾因全局序号冲突而静默丢弃的事件无法凭空恢复；迁移只保留数据库实际存在的原始记录。

## 一次完整录牌

1. 选择 6/7/8 副及桌规。打开“规则详情 / 补充字段”填写来源、座位上限、底牌机制、追加注结算、分 A 限制和是否从完整新靴开始。未知保留未知。
2. 点“新建牌靴（锁定规则）”。之后编辑表单只用于下个牌靴，顶部始终展示当前已锁定的副数。
3. 勾选下一轮参与座位，再点“新开一轮”。玩家最多 7 位，每轮可变化，未参与座位不能收牌。
4. 选择目标座位，用按钮录牌。`0=10`，`A/J/Q/K` 录对应牌，`T` 为十点未细分，`X` 为庄家暗牌；`G/B/V` 为停牌/加倍/分牌，`Ctrl+Z` 撤销。输入框内不会触发录牌快捷键。
5. 分牌后从“目标手牌”选择要补牌的一手。动作按钮会随有效状态启用；加倍只能补一张；未知牌不能按部分已知点数结算。
6. 揭示时选同一座位和手牌，切换到“揭示暗牌/未知牌”，点击牌面。同手多张未知牌时，先在时间线选中具体发牌事件。
7. 双方终局牌录完整后点“结束本轮并结算”。这是按已录终局作确定性记账；规则未知或不支持时会说明原因。庄家 BJ 涉及追加注时，仅支持明确声明“全部注损失”的情况。
8. 无法补齐时使用“结束本轮（未结算）”，填写原因后仍可继续下一轮；未知牌和缺口不会被清除。新轮继续沿用整靴；结束牌靴后必须新建牌靴才能录新轮。
9. 选中历史事件可修正牌面、烧牌数量、已核实的缺口或错误检查结果。每次纠错追加审计事件，若破坏后续动作则整体拒绝；可先逆序撤销相关后续事件再重新录入。
10. “查看选中时点”只重放至该事件，不使用后续揭示或纠错。“导出 JSON / CSV”保存完整事件；“导入 JSON / CSV”校验后原子导入。“恢复历史会话”继续旧会话，“备份数据库”保存一致的 SQLite 副本。

时间线保留来源和确认状态。旧版 CSV 缺少完整身份字段，仅供阅读；旧版 JSON 可导入并校验。相同事件 ID 只有内容相同才幂等，内容冲突会报错，不覆盖原记录。

## 运行检查

```powershell
python -m unittest discover -s tests -v
python -m blackjack_lab.main --check
python -m compileall -q blackjack_lab tests scripts
```

也可双击“运行测试.bat”。所有自动测试使用临时数据库、自建牌面事件，包含实际 Tk 窗口回调。`scripts/verify_release.py` 保存完整验收输出和源文件 SHA256；其中截图检查使用开发环境可选的 Pillow，产品本身不依赖 Pillow。

## 已验证范围与限制

- 6/7/8 副初始化、物理容量和十点桶联合约束；庄家与最多 7 座位；有限不放回记录。
- 事件去重、原子写入、追加撤销与纠错；JSON/完整 CSV 往返；旧库迁移、异常退出恢复。
- 确定性净收益以原始一单位为基准；分牌两手均不享受天然 Blackjack 赔付，加倍追加额计入损益。
- 右侧原牌面与分组数是“尚未确认移除的账面计数”，含未知底牌、烧牌和十点桶不确定性，不等于待发牌组成。记录无已知缺口也不代表分析引擎已实现。
- 界面验收为 1360×900 和 1180×800。最低窗口高度 800；未承诺更小屏幕、所有 DPI 或所有最大分牌布局。
- 未交付概率/EV、识别、捕获、实盘适配。每轮重置/未知牌靴模型不能建靴。规则纠错分支尚未实现，修改规则请新建牌靴。
- 仅原注损失等其他庄家 BJ 追加注结算未支持。没有计算庄家策略或自动补牌；已知 S17/H17 时会阻止过早结算。

代码按 `core / ledger / storage / ui` 分层；`analysis / simulator / vision / capture` 保留后续阶段目录。许可证与第三方边界见 `NOTICE.md`。
